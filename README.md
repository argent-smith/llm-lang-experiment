# Эксперимент к докладу RubyRussia 2026

Материалы эмпирической части доклада «На вкус и цвет все фломастеры
разные. Особенно если вы пишете на Ruby» — RubyRussia 2026, Москва,
2 октября 2026.

Результаты предварительные: `n = 1` на ячейку, это первые наблюдения, а не
готовые выводы.

## Гипотеза

ИИ-агенты неравнодушны к языку программирования не из-за качеств языка,
а из-за объёма его кода в обучающей выборке модели:

1. Python в фаворе, потому что это язык выбора самих авторов LLM.
2. JS/TypeScript в фаворе просто по массовости, безотносительно того,
   кто пишет модели.

Ruby не подпадает ни под одну из причин и по обеим должен проигрывать.
Вопрос — оправдан ли этот прогноз на данных, а не только по расхожим
мнениям.

## Метод

Для каждого языка с нуля реализуется один и тот же проект — Syncbox,
самостоятельно хостящееся файловое хранилище с синхронизацией. HTTP API
формально зафиксирован в [syncbox-openapi.yaml](docs/syncbox-openapi.yaml)
(OpenAPI 3.0), CLI — прозой в [SYNCBOX-SPEC.md](docs/SYNCBOX-SPEC.md), но
так же буквально одинаково для всех языков. Единая спецификация вместо
готового опенсорс-проекта — осознанный выбор: сопоставимых по масштабу
реальных проектов на всех языках эксперимента не существует, а готовый
популярный репозиторий модель могла запомнить построчно, что исказило бы
измерение эффекта языка.

Модель прогоняется через тикеты в фиксированном цикле: реализация →
саморевью на критические замечания → фикс → повторное ревью → повтор до
сходимости или явного отказа. Штатные тесты, acceptance-смок и контрактный
тест (Schemathesis по OpenAPI) — часть критерия «сошлось или сдалось».
Харнесс (Claude Code, `claude -p`) и модель (`claude-sonnet-5`, точным ID
на каждом вызове, `--effort xhigh`) зафиксированы и одинаковы для всех
языков — единственная переменная эксперимента — язык проекта. Весь код
тикета исполняется только в Docker-контейнере.

В эксперимент включены семь языков, но в доклад RubyRussia 2026 идут
только четыре:

- **В докладе:** Python, JavaScript, TypeScript, Ruby.
- **Вне доклада:** OCaml, Scala, Golang — метод тот же, но данные
  собираются про запас, для других исследований, и в доклад не входят.

По каждому тикету фиксируются число итераций, время и токены — точными
полями из JSON-вывода харнесса, а также кейсы провала (зацикливание,
повторяющиеся ошибки). Подробности гипотезы, полигона и метода — в
[CLAUDE.md](CLAUDE.md).

## Статус на 2 октября 2026

- Пройден весь стартовый бэклог из 11 тикетов на четырёх языках доклада:
  44 канонических прогона (канонический — единственный зачётный прогон на
  пару «язык × тикет»). Все сошлись, штатные тесты и контрактный тест
  зелёные.
- Прогоны собраны одной replay-кампанией 4–6 сентября под единой
  зафиксированной конфигурацией. Прежние прогоны ручной эры пилота
  остаются в архиве, но в сравнение не входят.
- Сравнение языков: [PILOT-COMPARISON-talk-languages.md](docs/PILOT-COMPARISON-talk-languages.md).
  По-тикетный журнал: [EXPERIMENT-LOG.md](docs/EXPERIMENT-LOG.md).
  Операционный отчёт о кампании: [REPLAY-CAMPAIGN-2026-09.md](docs/REPLAY-CAMPAIGN-2026-09.md).
- Данные по Go, OCaml и Scala собраны отдельно, на раннем этапе пилота,
  и в сравнение с четырьмя языками доклада не входят.
- Полный прогон (10–100 тикетов на язык) пока не начат: см. «Известные
  ограничения».

## Воспроизведение

Проверки, которые гоняет CI, запускаются локально одной командой:

```sh
make check
```

Предпосылки (Docker, `shellcheck`, `python3`, `node`/`npx`), список целей
Makefile и решения типичных проблем — в [docs/RUNBOOK.md](docs/RUNBOOK.md).

Запуск тикета через харнесс (`scripts/run-pilot-ticket.sh`,
`scripts/run-pilot-loop.sh`) требует токена `CLAUDE_CODE_OAUTH_TOKEN` в
`scripts/pilot-harness.env` (шаблон и инструкция —
`scripts/pilot-harness.env.example`) и платных вызовов модели: 44
канонических прогона обошлись примерно в 66 долларов. У подписки есть
оконный лимит использования; при его исчерпании вызов падает с `429`, а
оркестратор ждёт сброса окна.

## Известные ограничения

- **`n = 1` на ячейку.** Один канонический прогон на язык на тикет.
  Статистический тест на таких объёмах не осмыслен, нужен полный прогон.
- **Время Ruby завышено выбором образа.** Агент на Ruby во всех тикетах
  выбрал `FROM ruby:3.3`, а в образ харнесса заранее загружен только
  `ruby:3.3-slim`: холодная сборка образа занимает около 100 секунд на
  тикет и составляет большую часть work-времени Ruby. Это конфаундер
  стенда, а не языковой эффект; разбор — в
  [TALK-OUTLINE-rubyrussia-2026.md](docs/TALK-OUTLINE-rubyrussia-2026.md).
- **Публичность и контаминация.** В репозитории открыты эталонная
  реализация, acceptance-скрипты, спецификация и полные решения прошлых
  прогонов. На завершённые 44 прогона это не влияет: они шли при
  приватном репозитории. Но харнесс не запрещает агенту веб, поэтому до
  полного прогона нужно закрыть веб-доступ агента (см. пункт 4 в
  [CLAUDE.md](CLAUDE.md)); иначе агент сможет скачать готовые решения.
- **Транскрипты опубликованы как есть**, с заменой личных путей и
  названий рабочих проектов на `<user>` и `<work-project>`.
- **Время тикета 1 в отчёте сравнения.** Суммы «wall-мин» берут по
  тикету 1 только последнюю итерацию, а токены и стоимость — обе. На
  ранги это не влияет, но суммы времени занижены.

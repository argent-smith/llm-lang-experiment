# Эксперимент к докладу RubyRussia 2026

Материалы эмпирической части доклада «На вкус и цвет все фломастеры разные.
Особенно если вы пишете на Ruby» — RubyRussia 2026, Москва, 2 октября 2026
(дедлайн CFP — 1 сентября 2026).

## Гипотеза

ИИ-агенты неравнодушны к языку программирования не из-за качеств языка,
а из-за объёма его кода в обучающей выборке модели:

1. Python в фаворе, потому что это язык выбора самих авторов LLM.
2. JS/TypeScript в фаворе просто по массовости, безотносительно того,
   кто пишет модели.

Ruby не подпадает ни под одну из причин и по обеим должен проигрывать.
Вопрос — оправдан ли этот прогноз статистически, а не только на анекдотах.

## Метод

Для каждого языка с нуля реализуется один и тот же проект — Syncbox,
самостоятельно хостящееся файловое хранилище с синхронизацией. HTTP API
формально зафиксирован в [syncbox-openapi.yaml](docs/syncbox-openapi.yaml)
(OpenAPI 3.0), CLI — прозой в [SYNCBOX-SPEC.md](docs/SYNCBOX-SPEC.md), но так
же буквально одинаково для всех языков. Единая спецификация вместо
готового опенсорс-проекта — осознанный выбор: сопоставимых по масштабу
реальных проектов на всех шести языках не существует, а готовый
популярный репозиторий модель могла запомнить построчно, что исказило
бы измерение эффекта языка.

Модель прогоняется через тикеты в фиксированном цикле: реализация →
саморевью на критические замечания → фикс → повторное ревью → повтор до
сходимости или явного отказа. Харнесс и модель зафиксированы и одинаковы
для всех языков — единственная переменная эксперимента — язык проекта.

В эксперимент включены шесть языков, но в доклад RubyRussia 2026 идут
только три:

- **В докладе:** Python, JS/TS, Ruby.
- **Вне доклада:** OCaml, Scala, Golang — метод тот же, но данные
  собираются про запас, для других исследований, и в CFP не упоминаются.

По каждому тикету фиксируются число итераций, время, токены (если харнесс
их отдаёт) и отдельно — кейсы провала (зацикливание, повторяющиеся ошибки).

Подробности гипотезы, полигона и метода — в [CLAUDE.md](CLAUDE.md).

## Статус

Пилотная стадия (2–3 тикета на язык): проверяются устойчивость версии
модели в харнессе на протяжении прогона, доступность реальных цифр по
токенам и времени, а также то, что все шесть реализаций фактически
остаются в рамках спецификации Syncbox, а не расходятся между языками.
Полный прогон (10–100 тикетов на язык) начнётся только после того, как
пилот закроет все три пункта.

К моменту доклада (2 октября 2026) эксперимент не будет завершён — доклад
про гипотезу, дизайн эксперимента и первые наблюдения, а не про готовые
выводы.

## Локальный запуск

`make help` — список целей. `make check` гоняет то же самое, что CI
(`.github/workflows/acceptance.yml`): shellcheck, markdownlint, валидация
OpenAPI-схемы, acceptance-смок и контрактный тест против эталонной
реализации. `make run-server` / `make run-client` поднимают её вручную
для ручной проверки. Требуются `docker`, `shellcheck`, `python3`, `npx`.

## Файлы

- [CLAUDE.md](CLAUDE.md) — гипотеза, полигон, метод и ведение эксперимента.
- [Makefile](Makefile) — точка входа для проверок и запуска реализаций.
- [acceptance/](acceptance/) — smoke- и контрактный тест, годятся для
  любой из шести реализаций без изменений (`smoke.sh`, `contract-test.sh`,
  служебная эталонная реализация в `reference-impl/`, исполняется в
  Docker — обязательное условие для всех «стендов» эксперимента).
- `docs/` — содержательные документы:
  - [SYNCBOX-SPEC.md](docs/SYNCBOX-SPEC.md) — спецификация проекта,
    единого для всех шести языков.
  - [syncbox-openapi.yaml](docs/syncbox-openapi.yaml) — формальная
    OpenAPI-схема HTTP-поверхности, источник истины для контракта.
  - [CFP RubyRussia 2026.md](docs/CFP%20RubyRussia%202026.md) —
    черновик заявки на конференцию.
  - [Конспект разговора с ментором.md](docs/Конспект%20разговора%20с%20ментором.md)
    — конспект исходного разговора, из которого выросла тема доклада.

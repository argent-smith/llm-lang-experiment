# Массовость языков доклада на рынке — внешние данные (2025–2026)

Справочный срез для преамбулы доклада RubyRussia 2026 и для раздела
«Отношение к гипотезе» в
[`docs/PILOT-COMPARISON-talk-languages.md`](PILOT-COMPARISON-talk-languages.md).
Языки — четыре языка доклада: Python, JavaScript, TypeScript, Ruby
(CLAUDE.md, «Языки доклада»).

Данные собраны 2026-09-04 из публичных источников (см. «Источники»).
Все цифры внешние, к пилотному эксперименту отношения не имеют — это
контекст рынка, а не измерение.

## Зачем разделять два измерения

Гипотеза доклада (CLAUDE.md) объясняет расположение агента к языку
**объёмом кода этого языка в обучающей выборке модели**. Это не то же
самое, что «сколько разработчиков пишет на языке сейчас»:

- **Кто пишет сейчас** — потоковая величина, меняется за год-два.
  Отражает моду, дефолты фреймворков, найм.
- **Сколько кода накоплено** — интегральная величина, отражает возраст
  языка в проде. Именно она ближе к тому, что попадает в обучающий
  корпус.

Для Python, JavaScript и Ruby оба измерения дают один и тот же порядок.
**Для TypeScript они расходятся** — и это единственный язык доклада, по
которому формулировку CFP приходится уточнять.

## Измерение 1: кто пишет сейчас

| Источник (метрика)                            | Python      | JavaScript | TypeScript  | Ruby        |
| --------------------------------------------- | ----------- | ---------- | ----------- | ----------- |
| Stack Overflow 2025, все респонденты          | 57.9%       | 66.0%      | 43.6%       | 6.4%        |
| Stack Overflow 2025, профессионалы            | 54.8%       | 68.8%      | 48.8%       | 6.9%        |
| GitHub Octoverse 2025, контрибьюторы (авг-25) | №2 (~2.6M)  | №3 (2.15M) | №1 (2.64M)  | не в топ-10 |
| RedMonk, январь 2026                          | №2          | №1         | №6          | №9          |
| TIOBE, август 2026 (поисковые запросы)        | №1 (18.53%) | №6 (2.63%) | №44 (0.37%) | №16 (0.98%) |
| PYPL, весна 2026 (поиск туториалов)           | №1 (~36%)   | №3         | ниже топ-5  | ниже топ-5  |

По любой метрике, которая меряет **использование**, а не поисковые
запросы, TypeScript — язык топ-4—6. По числу уникальных месячных
контрибьюторов на GitHub в августе 2025 он **впервые вышел на первое
место**, обойдя Python (на ~42 тыс.) и JavaScript (на ~0.5 млн). Годовой
рост числа контрибьюторов: TypeScript +66.6%, Python +48%,
JavaScript +24.8%.

TIOBE и PYPL занижают TypeScript структурно: обе метрики считают
поисковые запросы, а на TypeScript чаще ищут как «javascript …». К
абсолютным местам TypeScript в этих двух индексах относиться как к
сигналу нельзя — но Python №1 и падение Ruby они показывают согласованно
с остальными.

## Измерение 2: сколько кода накоплено

The Stack v2 — крупнейший открытый корпус исходного кода (основа
StarCoder2, собран BigCode совместно с Software Heritage). Объём после
дедупликации, Таблица 1 статьи (arXiv:2402.19173):

| Язык       | Объём (ГБ) | Файлов (млн) |
| ---------- | ---------- | ------------ |
| JavaScript | 1 115.42   | 108.87       |
| Java       | 548.00     | 154.28       |
| C++        | 353.89     | 43.18        |
| C#         | 239.89     | 51.23        |
| Python     | 233.29     | 56.93        |
| PHP        | 224.59     | 46.03        |
| C          | 202.05     | 20.78        |
| TypeScript | 61.01      | 23.85        |
| Go         | 54.60      | 9.30         |
| Ruby       | 31.70      | 17.79        |

При составлении обучающего микса BigCode **специально даунсэмплил
JavaScript и Java до 200 ГБ** ради равномерности — то есть даже в
намеренно уравненном миксе JavaScript остаётся втрое больше TypeScript.

По токенам (StarCoder2Data, вторичная оценка): Python ~50.6 млрд,
JavaScript ~45.3 млрд, C++ ~69.7 млрд, **TypeScript ~12.2 млрд**,
**Ruby ~5.76 млрд**.

Сводя оба измерения: по сырому объёму TypeScript меньше Python вчетверо,
а JavaScript — на порядок с лишним (61 против 233 и 1 115 ГБ). По
токенам и по намеренно уравненному обучающему миксу (JavaScript
даунсэмплен до 200 ГБ) разрыв — **в 3–4 раза и к Python, и к
JavaScript**. В любом варианте счёта TypeScript **лишь примерно вдвое
больше Ruby** и в разы меньше двух других языков доклада.

## Что это значит для TypeScript

- **«Массовость» TypeScript реальна, но это молодая, adoption-массовость,
  а не корпусная.** TypeScript опубликован в 2012, инфлексия массового
  внедрения — вторая половина 2010-х (≈2018–2021). JavaScript и Python
  копили код по 15–30 лет; TypeScript — около 7.
- **По корпусному измерению — тому, на которое опирается механизм
  гипотезы, — TypeScript ближе к Ruby, чем к JavaScript.** Группировка
  CFP «JavaScript и TypeScript оба в фаворе по массовости, один
  механизм» на этой оси не держится: у JavaScript корпус есть, у
  TypeScript пока нет.
- **Риск циркулярности, который стоит проговорить со сцены.** GitHub в
  отчёте Octoverse 2025 прямо связывает выход TypeScript на №1 с тем,
  что (а) типизированные языки надёжнее для ИИ-агентов, (б) фреймворки
  (Next.js, Astro, React) скаффолдят TypeScript по умолчанию,
  (в) проверка типов ловит «94% ошибок компиляции в коде от LLM». Если
  ИИ-тулинг сам разгоняет внедрение TypeScript, то «TypeScript
  массовый» и «модель расположена к TypeScript» перестают быть
  независимыми: будущие корпуса получат больше TypeScript *потому что*
  так решили дефолты фреймворков и поведение моделей.
- **Пилот с этим согласуется, но не доказывает.** В
  [`PILOT-COMPARISON-talk-languages.md`](PILOT-COMPARISON-talk-languages.md)
  TypeScript дороже Python на всех трёх методических стратах
  (×1.27–1.43). Это совместимо с «корпус TypeScript тоньше, чем кажется
  по adoption», но отчёт честно оставляет и альтернативу: лишний слой
  `tsc` + `tsconfig` как реальная работа, а не немилость к языку.

## Что это значит для Ruby

Ruby — самый малый из четырёх по **обоим** измерениям, без исключений:

- Stack Overflow 2025: ~6–7% (против 44–49% у TypeScript).
- RedMonk: №9, тренд многолетнего снижения.
- GitHub Octoverse 2025: вне топ-10 (топ-10: TypeScript, Python,
  JavaScript, Java, C#, PHP, Shell, C++, HCL, Go).
- The Stack v2: 31.7 ГБ — вдвое меньше даже TypeScript, в 35 раз меньше
  JavaScript.

Эта часть посылки гипотезы («Ruby не язык большинства») внешними данными
подтверждается уверенно.

## Оговорки про сами метрики

- **Stack Overflow** — самоотбор респондентов, перекос в веб и
  раннюю карьеру. «Доля использующих» ≠ «доля кода».
- **GitHub Octoverse** — считает уникальных контрибьюторов за месяц:
  один коммит в один `.ts`-файл весит столько же, сколько месяц работы
  дата-сайентиста на Python. GitHub перекошен в веб и OSS. В
  «TypeScript-репозиториях» много сгенерированного `.js`, `.d.ts`,
  конфигов.
- **RedMonk** — корреляция обсуждения и использования (GitHub PR + Stack
  Overflow), не прямое измерение; сами авторы называют это индикатором
  тренда, а не доли рынка.
- **TIOBE, PYPL** — поисковые запросы. Занижают языки с хорошей
  документацией и сильной LLM-поддержкой (меньше поводов гуглить) и
  языки-надмножества (ищут по имени базового языка).
- **The Stack v2** — корпус кода с GitHub. Закрытые модели (в т. ч.
  Claude) учатся и на других источниках; но относительные пропорции
  языков в открытом корпусе — лучший публичный прокси того, чего в
  обучающих данных больше.

## Как это ложится в гипотезу CFP

Прогноз CFP: Python в фаворе как язык авторов LLM; JavaScript и
TypeScript — по массовости; Ruby проигрывает по обеим причинам. Внешние
данные:

- **Python — массовость подтверждается** (№1 или №2 везде; №1 по
  корпусу среди динамических языков высокого уровня).
- **JavaScript — массовость подтверждается по обоим измерениям**
  (№1 RedMonk, №3 контрибьюторы, №1 по объёму корпуса).
- **TypeScript — массовость подтверждается только по adoption, не по
  корпусу.** Для доклада: не объединять JavaScript и TypeScript в один
  «массовый» механизм не глядя — по объёму кода это разные весовые
  категории.
- **Ruby — «не язык большинства» подтверждается** по всем метрикам.

Всё вышеперечисленное — рыночный контекст, а не результат эксперимента.
Он не проверяет гипотезу (объём кода в обучающей выборке против того,
справляется ли агент с тикетами) — он только уточняет, какое из двух
пониманий «массовости» брать, когда гипотезу формулируют вслух.

# Сравнительный отчёт: Python vs Go (пилот, 2026-08-20)

Оба пилота — 3 тикета на язык, метод из CLAUDE.md. Python идёт в
доклад RubyRussia 2026, Go — нет (данные про запас, см. CLAUDE.md,
«Языки вне доклада»). Ниже — сравнение по фактически принятым
(валидным) прогонам; полная построчная запись, включая аннулированные
попытки, — в [`docs/EXPERIMENT-LOG.md`](EXPERIMENT-LOG.md).

«Время» везде ниже — `duration_ms` конкретного вызова `claude -p`
(точное определение — раздел «Лог» в [CLAUDE.md](../CLAUDE.md)), не
календарное время работы над тикетом: не включает паузы между
попытками (переигровки, ожидание решений человека по ходу пилота) и не
может их включать — headless-вызов не имеет точки, где мог бы
остановиться и ждать кого-то.

## Важная оговорка: харнесс не идентичен между языками

Это не финальное сравнение «язык против языка» — оно наблюдение о
пилотной, а не полномасштабной фазе. Python и Go прогонялись под
**разными версиями** `scripts/run-pilot-ticket.sh`:

- Все три тикета Python прогнаны **до** того, как на Go нашлись и
  закрылись `sandbox.allowUnsandboxedCommands` (лазейка через
  `dangerouslyDisableSandbox`) и Docker-сетевые/файловые ограничения
  (`network.allowedDomains`, `filesystem.allowWrite` для
  `~/.docker/buildx`).
- Тикет 1 Go прогнан при ещё открытой лазейке
  `dangerouslyDisableSandbox` (ей воспользовались 18 раз, утечки не
  было, но лазейка была реальной). Тикеты 2–3 Go — уже под полностью
  исправленным харнессом.

Значит: неизвестно, столкнулся бы Python с той же Docker-сетевой
стеной, если бы его гоняли под финальным харнессом — на его прогонах
лазейка `dangerouslyDisableSandbox` ещё была открыта и могла молча
маскировать ту же проблему, как это произошло на тикете 1 Go. Прямое
сравнение «у Go было больше трений с харнессом» **не** обязательно
означает языковой эффект — это может быть целиком артефакт того, в
каком порядке прогонялись языки относительно фиксов. Для строгого
сравнения Python стоит переиграть под финальной версией харнеса перед
переходом к полному прогону — рекомендация, не выполненное действие.

**Итого (только принятые прогоны):** Python — 8.1 мин, $2.33.
Go — 12.8 мин, $3.03.

**Итого (все попытки, включая аннулированные и харнесс-сбои)** —
честная стоимость пилота, а не только удачных прогонов: Python — 47.6
мин, $9.76 (8 прогонов, из них 5 не засчитаны как валидные данные).
Go — 17.9 мин, $4.31 (5 прогонов, из них 2 не засчитаны). У Python
общая сумма выше почти вдвое, но это тоже не «Python сложнее» —
основная масса аннулированных попыток Python (5 из 8) вызвана
инфраструктурными находками (устаревшая копия спецификации,
непредсказуемость `--permission-mode dontAsk`), которые исторически
были найдены раньше, на Python как на первом языке пилота — Go
унаследовал уже частично исправленный харнесс.

Итог: по чистой стоимости принятых данных Go дороже Python примерно на
30% ($3.03 против $2.33) и медленнее почти на 60% (12.8 мин против 8.1
мин) — но это единственное прямое, не искажённое очерёдностью фиксов
сравнение, и на 3 тикетах о статистической значимости говорить рано.

## Соответствие спецификации

Отклонений от `docs/SYNCBOX-SPEC.md`/`docs/syncbox-openapi.yaml` не
найдено ни на одном тикете ни одного языка: HTTP-коды и форма JSON
совпадают дословно, границы тикетов соблюдены в обе стороны (ни один
самоотчёт не забежал вперёд на traversal-защиту/атомарность/DELETE, ни
один не пропустил часть объявленного тикета). Риск 2 пилотной фазы
(«соответствие спецификации между языками», CLAUDE.md, «Сначала
пилот») пока не даёт повода для тревоги — но и настоящего сравнения
пока нет, потому что сравнивать не с чем: оба языка одинаково точны.

## Поведенческие отличия (наблюдение по существу гипотезы, не находка методики)

- **Штатные тесты.** Go написал юнит-тесты на всех трёх тикетах без
  явного требования в промпте. Python не написал ни одного — вместо
  этого каждый раз проверял вручную через `curl`. Разница воспроизвелась
  трижды подряд на каждом языке — не случайность одного прогона.
- **Формат `modified_at`.** Оба валидны как ISO 8601 UTC, но по-разному:
  Go — `...Z` с миллисекундами, Python — `...+00:00` с микросекундами.
  Спецификация не требует конкретного формата строки, только
  «ISO 8601 UTC» — не нарушение, просто разные конвенции по умолчанию
  в стандартных библиотеках.
- **Внутренние шаги (`num_turns`).** У Python тикеты в среднем короче
  по числу внутренних шагов (39→25→17, убывающий тренд — модель
  «нарабатывает» контекст проекта). У Go тикеты 2–3 выше, чем можно
  было бы ожидать по той же логике (36→33→25) — вероятно, частично
  из-за диагностики Docker-заминок внутри сессий, а не только из-за
  сложности самой задачи. Эта метрика для Go этой пилотной партии
  зашумлена харнесс-трением сильнее, чем для Python — ещё один довод
  переиграть Python под финальным харнессом перед прямым сравнением.

## Рекомендация

Прежде чем масштабировать пилот на оставшиеся четыре языка (Ruby,
TypeScript, OCaml, Scala), стоит решить: переигрывать ли Python
(3 тикета) под полностью финальной версией `scripts/run-pilot-ticket.sh`
(со всеми фиксами: синхронизация спецификации, `--dangerously-skip-permissions`,
`allowUnsandboxedCommands: false`, `network.allowedDomains`,
`filesystem.allowWrite` для buildx) — иначе Python и все последующие
языки формально прогоняются под разными версиями харнеса, что CLAUDE.md
прямо называет риском несравнимости тикетов.

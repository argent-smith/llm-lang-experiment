Продолжаем проект Syncbox (тикеты 1-7 — каркас сервера, happy path для PUT/GET блоба, список блобов, удаление блоба, защита от directory traversal, атомарность записи при параллельных PUT, клиент push — уже сделаны в этом же репозитории, плюс несколько фиксов серверной обработки граничных значений key). Тикет 8: клиент, команда pull.

Полная спецификация — в файлах SYNCBOX-SPEC.md и syncbox-openapi.yaml в корне этого репозитория — прочитай перед началом, если нужно освежить детали.

Нужно реализовать:

- Команду syncbox pull <dir> --server <url> у CLI-клиента (исполняемый файл syncbox, см. раздел «CLI (обязательный контракт)» спецификации): получить список блобов с сервера (GET /blobs), и для каждого блоба, которого нет в <dir> локально или который отличается от локальной версии по SHA-256, скачать его (GET /blobs/{key}) и записать в <dir> по относительному POSIX-пути, равному key, создавая недостающие поддиректории. Файлы, идентичные по содержимому серверной версии, повторно не скачивать. Это зеркальное отражение push из тикета 7.
- Ключ блоба — относительный POSIX-путь файла внутри <dir> (та же конвенция key, что и на сервере и в push).
- pull не удаляет локальные файлы, которых нет на сервере (удаление лишнего — это семантика sync/отдельные тикеты, для pull не специфицирована) — pull только скачивает недостающее и различающееся, ровно как push из тикета 7 не удалял лишнее на сервере.
- --server обязателен; то же значение можно задать переменной окружения SYNCBOX_SERVER — как описано в спецификации.
- Обёртка запуска: исполняемый файл run-client в корне репозитория уже принимает все четыре подкоманды по интерфейсу (тикет 7); теперь run-client pull <dir> --server <url> должен выполнять реальную работу вместо сообщения «пока не реализовано».
- Клиент, как и сервер, исполняется в Docker-контейнере через docker compose, не напрямую на хосте — то же требование раздела «Docker-изоляция», уже выполненное для push в тикете 7.

Границы этого тикета:

- status/sync — отдельные будущие тикеты (9-10), не входят. run-client должен по-прежнему принимать их по интерфейсу (status/sync <dir> --server <url>), но для status/sync остаётся понятное сообщение о том, что команда пока не реализована, и ненулевой код возврата — вместо необъяснимого падения.
- Полная обработка сетевых ошибок и частичных сбоев (недоступный сервер, часть файлов не скачалась) — отдельный будущий тикет (11), не входит. Базовая реакция на явный сбой (например, сервер недоступен) должна быть вменяемой — не проходить молча и не зависать, — но не обязана покрывать весь объём раздела «Коды возврата и ошибки» спецификации (детальный формат отчёта по частичным сбоям, коды возврата под конкретные случаи) — это тикет 11.

Не реализовывай перечисленное выше заранее — не входит в объём этого тикета.

Библиотеки, HTTP-клиент и внутреннее устройство — на твоё усмотрение, как и в предыдущих тикетах.

Версия языка в этом проекте зафиксирована: Node.js 20, базовый Docker-образ node:20-bookworm-slim (FROM node:20-bookworm-slim в Dockerfile). Не меняй версию языка и базовый образ.

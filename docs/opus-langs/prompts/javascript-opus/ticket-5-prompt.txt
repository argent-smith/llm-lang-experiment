Продолжаем проект Syncbox (тикеты 1-4 — каркас сервера, happy path для PUT/GET блоба, список блобов, удаление блоба — уже сделаны в этом же репозитории). Тикет 5: защита от directory traversal в key.

Полная спецификация — в файлах SYNCBOX-SPEC.md и syncbox-openapi.yaml в корне этого репозитория — прочитай перед началом, если нужно освежить детали.

Нужно реализовать:

- Сервер обязан отклонять key, содержащий `..` (переход на уровень выше) или являющийся абсолютным путём, кодом 400 — на всех эндпоинтах, принимающих key (PUT /blobs/{key}, GET /blobs/{key}, DELETE /blobs/{key}).
- То же касается key, который не удаётся безопасно представить как путь к файлу на файловой системе сервера (например, некорректная кодировка после декодирования URL) — тоже 400, а не падение сервера или 500.
- Проверка должна быть надёжной против обхода: не полагайся только на текстовый поиск подстроки `..` — итоговый путь на диске после разрешения (resolve/normalize) должен оставаться строго внутри корня хранилища.

Границы этого тикета:

- Атомарность записи при параллельных PUT — отдельный будущий тикет, в этот не входит.
- Клиентские команды (push/pull/status/sync) — отдельные будущие тикеты, не входят.

Не реализовывай перечисленное выше заранее — не входит в объём этого тикета.

Сервер по-прежнему должен исполняться в Docker-контейнере через docker compose — не переделывай эту часть, если она уже работает, расширяй по необходимости.

Библиотеки и внутреннее устройство — на твоё усмотрение, как и в предыдущих тикетах.

Версия языка в этом проекте зафиксирована: Node.js 20, базовый Docker-образ node:20-alpine (FROM node:20-alpine в Dockerfile). Не меняй версию языка и базовый образ.

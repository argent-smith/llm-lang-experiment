Code quality не критерий исхода (таблица CI-проверок — в `CLAUDE.md`,
раздел «Метод») — колонка только для сбора данных. Тулинг
(`scripts/run-code-quality.sh`: ruff для Python, golangci-lint для Go)
появился 2026-08-20, после того как все тикеты Python и Go уже
прошли — для этих строк помечено «н/д», кроме последнего тикета
каждого языка (финальное состояние кода), проверенного ретроактивно
один раз, не по каждому отдельному тикету (пилотные директории не
git-репозитории, промежуточных срезов нет). Подробности — в
[`docs/PILOT-RESULT-python-ticket-1.md`](PILOT-RESULT-python-ticket-1.md#code-quality-ретроактивно)
и [`docs/PILOT-RESULT-go.md`](PILOT-RESULT-go.md#code-quality-ретроактивно).

Code security пробовали в тот же день (bandit для Python, gosec для
Go) и убрали: сравнение находок между языками оказалось неинформативно
для гипотезы эксперимента — числа отражали в первую очередь разное
покрытие правил между инструментами (`bandit` не ловит path traversal
из коробки, `gosec` ловит), а не разницу в безопасности кода. Разбор —
[`docs/PILOT-COMPARISON-python-go.md`](PILOT-COMPARISON-python-go.md#code-quality--code-security-исключено).

«Итерации» здесь — число вызовов `claude -p`/`--resume` в цикле
реализация → саморевью → фикс, не `num_turns` внутри одного вызова
(вызов выше был единственным, `num_turns=42` — это внутренние шаги
одного вызова, а не отдельные итерации цикла).

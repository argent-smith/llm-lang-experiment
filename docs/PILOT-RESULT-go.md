# Результат пилота: Go

## Итог

Пилот Go (3 тикета, второй язык эксперимента, вне доклада RubyRussia
2026) три раунда. Раунд 1 (2026-08-20, старый харнесс) — тикет 1
сошёлся с первой попытки, тикет 2 потребовал трёх попыток (не из-за
модели, а из-за двух реальных ограничений песочницы, см. отдельные
инциденты ниже), тикет 3 сошёлся с первой попытки. Раунд 2 (2026-08-24,
Docker-обвязанный харнесс, см.
[инцидент](incidents/2026-08-21-write-tool-sandbox-escape/README.md))
— все три тикета сошлись с первой попытки, но харнес не фиксировал
`--effort` явно, и дефолт CLI оказался `high`, не `xhigh`. Раунд 3
(2026-08-24/25, `--effort xhigh` явно) — **канонические данные пилота
Go**, тикет 2 столкнулся с реальным `429 session limit` на первой
попытке (первый живой сигнал риска 3 пилотной фазы), вторая попытка
после сброса лимита сошлась.

## Аудит соответствия спецификации (Go, тикеты 1–3) и сравнение с Python

Изначально проведён на старом харнессе (2026-08-20), повторно
подтверждён вручную на канонических прогонах Docker-харнеса (2026-08-25,
`effort=xhigh`, `session_id` из разделов выше) — прямой `curl` к
`run-server`, независимая сверка `sha256`/`size`.

- HTTP-поверхность реализована буквально по спецификации: коды ответов
  и форма JSON совпадают дословно с Python, лишних полей/эндпоинтов
  нет.
- Границы тикетов соблюдены в обе стороны на всех трёх тикетах — ни
  разу не забежал вперёд (traversal-защита, атомарность, DELETE
  явно оставлены будущим тикетам во всех самоотчётах) и не пропустил
  часть объявленного тикета.
- **Отличие от Python, не являющееся нарушением спецификации:** на
  канонических прогонах (2026-08-25) `modified_at` у Go — `...Z` без
  дробных секунд (`2026-08-25T17:35:08Z`), у Python — `...Z` с
  микросекундами (`2026-08-25T14:43:01.698433Z`) — та же разница, что
  и на предыдущем (раунд 2) прогоне, устойчива между независимыми
  генерациями кода одного языка. Оба — валидный ISO 8601 UTC,
  спецификация не требует конкретного формата строки.
- Штатные тесты: на старом харнессе Python не написал ни одного теста
  ни на одном тикете, Go — писал на всех трёх без явного требования в
  промпте. На Docker-харнессе (начиная с раунда 2) оба языка написали
  тесты на всех тикетах — `SYNCBOX-SPEC.md` с 2026-08-20 явно требует
  штатные тесты, чего не было в силе для Python на прогонах старого
  харнеса. Разница исчезла не потому, что языковой эффект пропал, а
  потому что сам промпт/спецификация изменились — не путать одно с
  другим.

Итог по риску 2 («соответствие спецификации между языками», CLAUDE.md,
«Сначала пилот»): на всех трёх раундах и на обоих языках пилота
отклонений от спецификации не найдено ни на одном тикете — сравнивать
пока не с чем содержательно (различий в соблюдении контракта нет), но
данных уже достаточно, чтобы риск не выглядел тревожным на этой
стадии.

## Code security

Code security (gosec) гоняли на старом прогоне — 14 находок, из них
4 HIGH (все про path traversal: `key` из URL без проверки на `..` —
ожидаемо, защита сознательно отложена до тикета 5). Проверку убрали из
метода: см.
[`docs/PILOT-COMPARISON-python-go.md`](PILOT-COMPARISON-python-go.md#code-security-исключено)
— на Python тот же самый паттерн, bandit его просто не ловит, и
сравнение находок между языками оказалось не про безопасность кода, а
про покрытие правил инструментов.

Полная построчная запись всех прогонов —
[`docs/EXPERIMENT-LOG.md`](EXPERIMENT-LOG.md). Статус трёх рисков
пилотной фазы после переигровки Python+Go на Docker-харнессе под
`effort=xhigh` — см.
[`docs/PILOT-RESULT-python-ticket-1.md`](PILOT-RESULT-python-ticket-1.md#что-дальше).

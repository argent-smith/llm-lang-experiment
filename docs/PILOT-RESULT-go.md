# Результат пилота: Go

## Итог

Пилот Go (3 тикета, второй язык эксперимента, вне доклада RubyRussia
2026) завершён. Тикет 1 сошёлся с первой попытки. Тикет 2 потребовал
трёх попыток — не из-за модели, а из-за двух реальных ограничений
песочницы, которые ранее маскировала теперь закрытая лазейка
`dangerouslyDisableSandbox` (см. отдельные инциденты ниже). Тикет 3
сошёлся с первой попытки под уже исправленным харнессом, без единой
заминки.

## Аудит соответствия спецификации (Go, тикеты 1–3) и сравнение с Python

- HTTP-поверхность реализована буквально по спецификации: коды ответов
  и форма JSON совпадают дословно с Python, лишних полей/эндпоинтов
  нет.
- Границы тикетов соблюдены в обе стороны на всех трёх тикетах — ни
  разу не забежал вперёд (traversal-защита, атомарность, DELETE
  явно оставлены будущим тикетам во всех самоотчётах) и не пропустил
  часть объявленного тикета.
- **Отличие от Python, не являющееся нарушением спецификации:**
  `modified_at` — Go форматирует как `...Z` (миллисекунды, суффикс
  `Z`), Python — как `...+00:00` (микросекунды, суффикс со знаком).
  Оба — валидный ISO 8601 UTC, спецификация не требует конкретного
  формата строки, только «ISO 8601 UTC» — интересная точка для
  будущего сравнения между языками (единообразия форматов ISO 8601 у
  моделей нет само по себе), не дефект ни одной из реализаций.
- Штатные тесты: в отличие от Python (не писал тесты ни на одном
  тикете), на Go модель написала юнит-тесты на всех трёх тикетах — это
  наблюдение по существу гипотезы эксперимента (стиль тестирования,
  видимо, зависит от языка/конвенций в обучающей выборке), а не
  методологическая находка.

Итог по риску 2 («соответствие спецификации между языками», CLAUDE.md,
«Сначала пилот»): на первых двух языках пилота отклонений от
спецификации не найдено ни на одном тикете — сравнивать пока не с чем
содержательно (различий в соблюдении контракта нет), но данных уже
достаточно, чтобы риск не выглядел тревожным на этой стадии.

## Code quality (ретроактивно)

Тот же ретроактивный скан финального состояния кода (после тикета 3),
что и на Python — см. оговорку в
[`docs/PILOT-RESULT-python-ticket-1.md`](PILOT-RESULT-python-ticket-1.md#code-quality-ретроактивно).
Не входит в критерий «сошлось/сдалось».

**golangci-lint (quality, конфиг `scripts/code-quality-configs/go/golangci.yml`
— errcheck/govet/ineffassign/revive/staticcheck/unused/gocyclo/funlen/dupl,
версия 2.13.1):** 9 находок — `errcheck` ×6 (непроверенное значение
ошибки на `f.Close()`, 3 места, и `json.NewEncoder(w).Encode(...)`,
3 места, в `internal/server/server.go`), `revive` ×2
(`unused-parameter` — параметр `r` не используется), `funlen` ×1
(`TestListBlobs` длиннее порога на одну строку — 61 против 60).
`errcheck`-находки типовые, невысокого риска — закрытие файла и запись
ответа клиенту редко проверяют на ошибку в простых обработчиках,
большинство линтер-конфигов относится к этому терпимо по умолчанию.

Code security (gosec) тоже гоняли в тот же день — 14 находок, из них
4 HIGH (все про path traversal: `key` из URL без проверки на `..` —
ожидаемо, защита сознательно отложена до тикета 5). Проверку убрали из
метода: см.
[`docs/PILOT-COMPARISON-python-go.md`](PILOT-COMPARISON-python-go.md#code-quality--code-security-исключено)
— на Python тот же самый паттерн, bandit его просто не ловит, и
сравнение находок между языками оказалось не про безопасность кода, а
про покрытие правил инструментов.

Полная построчная запись всех прогонов —
[`docs/EXPERIMENT-LOG.md`](EXPERIMENT-LOG.md). Статус трёх рисков
пилотной фазы после Python и Go — см.
[`docs/PILOT-RESULT-python-ticket-1.md`](PILOT-RESULT-python-ticket-1.md#что-дальше)

Проверка снаружи (реальный вызов run-client push с обычной командной строки, без дополнительных аргументов после --server) нашла баг в текущей реализации тикета 7 (клиент push, только что сделан в этом же репозитории). Нужно исправить.

Симптом: на хосте, где /bin/bash — более старая версия (GNU bash 3.2, без возможностей bash 4.4+; так выглядит системный /bin/bash на macOS — Apple годами не обновляет его из-за лицензии), вызов run-client push <dir> --server <url> без каких-либо дополнительных аргументов после --server падает ещё до вызова docker compose:

run-client: line 61: ARGS[@]: unbound variable

Похоже, run-client собирает необязательные дополнительные аргументы в bash-массив и разворачивает его как "${ARGS[@]}" под set -u (nounset). На bash 3.2 (и вообще на любом bash до 4.4) раскрытие "${массив[@]}" для массива, в который ничего не было добавлено, считается обращением к неприсвоенной переменной под nounset и завершает скрипт ошибкой — именно это и происходит при самом обычном вызове (push <dir> --server <url> без ничего лишнего).

Нужно:

- Исправить run-client так, чтобы push (и в целом любая команда) корректно отрабатывала под set -u при пустом наборе дополнительных аргументов — независимо от версии bash, включая версии старше 4.4. Один из рабочих способов — использовать "${ARGS[@]+"${ARGS[@]}"}" вместо "${ARGS[@]}" в месте вызова docker compose run; подойдёт и любой другой способ, дающий тот же результат.
- Не полагаться в этом скрипте на возможности bash, появившиеся в 4.4 и позже — конвенция запуска (run-server/run-client) должна работать на разных хостах, а не только там, где сам агент её тестирует.
- После фикса — самостоятельно перепроверь: run-client push <dir> --server <url> без дополнительных аргументов должен отрабатывать без падения на "unbound variable" под set -u при пустом ARGS (например, временно добавь set -u в тестовый мини-скрипт с пустым массивом и такой же раскруткой, чтобы убедиться, что конкретно твой фикс годится, не только конкретно этот вызов).

Остальная функциональность push (сравнение SHA-256, загрузка отсутствующих/изменившихся файлов, --server/SYNCBOX_SERVER, работа в Docker через docker compose) уже реализована и не нуждается в изменениях — правь только эту конкретную проблему.

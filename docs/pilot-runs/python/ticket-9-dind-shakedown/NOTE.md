# ticket-9-dind-shakedown (Python) — обкатка Docker-in-Docker харнеса

Не канонический тикет. Первый реальный прогон тикета через новый
харнесс на **Docker-in-Docker** (переход с Docker-out-of-Docker, разбор —
`docs/incidents/2026-09-01-dood-host-fs-reachable/`). Цель — убедиться,
что новый барьер не только закрывает утечку (проверено синтетически в
тот же день), но и не ломает нормальный цикл: агент внутри контейнера
харнеса поднимает свой `dockerd`, собирает и гоняет `docker compose`
код тикета в нём, сходится, архивируется, гейты зелёные.

Сессия `fc654d4b-8e75-4feb-9ff6-0f985a5fafb0`: 26 ходов, $1.59,
`is_error=false`, сошлось за 1 итерацию авто-лупа. Гейты: run-tests
pass (155 passed), contract 3/3, smoke info 10/13 (шаг 10 `status`
зелёный; 08/09/11 — sync-зависимы, тикет 10) — тот же чистый результат,
что у канонического Python-прогона тикета 9 на DooD.

Промпт — копия `.ticket-9-prompt.txt` (тот же текст, что у 4 языков
доклада). Канонический снапшот Python для тикета 9 — по-прежнему
`docs/pilot-runs/python/ticket-9/53e0dd58-.../` (прогон на DooD,
независимо перепроверенный вместе с остальными тремя языками). Этот
каталог — доказательство работоспособности харнеса, не замена
канона.

Первая попытка обкатки (`e6a144f5-...`, не сохранена) упала на API
`429 session limit` за 9 с, до какой-либо работы — не про харнесс.

# Архив прогонов пилота

Полный набор входных и выходных данных по каждой попытке каждого
тикета — промпт, копия спецификации/схемы, которую видел агент, и
результат вызова (`--output-format json`). Ничего не скрыто и не
сглажено: аннулированные и провальные попытки архивированы наравне с
принятыми — сводки в `docs/EXPERIMENT-LOG.md` и `docs/PILOT-RESULT-*.md`
опираются на эти файлы, а не наоборот.

Структура: `<язык>/ticket-<N>/attempt-<M>-<session_id>-<исход>/`, в
каждой попытке:

- `prompt.txt` — тикет, буквально то, что подавалось на stdin `claude -p`.
- `SYNCBOX-SPEC.md`, `syncbox-openapi.yaml` — копия спецификации/схемы
  в директории пилота на момент этого вызова (не всегда идентична
  текущей `docs/SYNCBOX-SPEC.md` меты — см. находку про устаревшую
  копию в
  [инциденте](../incidents/2026-08-19-python-ticket1-contamination/README.md#устаревшая-копия-спецификации-2026-08-20)).
- `result.json` — сырой вывод `--output-format json`: модель, effort,
  токены, стоимость, время, `session_id`, итоговый самоотчёт модели.
- `code/` — код, который написал агент (полный снимок директории
  пилота на момент этой попытки, без служебных файлов вроде
  `.ticket-N-prompt.txt`). Пока архивирован только для шести
  принятых («сошлось») попыток — по одной на тикет каждого языка;
  для аннулированных/провальных попыток кода нет (это можно
  добавить позже из `syncbox-python.stale-spec-2026-08-19`/
  `syncbox-python.dontask-2026-08-20`, которые сохранены на хосте
  как улика, но не задача этого коммита).
- `quality-quality.json` — code quality по этому конкретному коду
  (`scripts/run-code-quality.sh`, конфиг из
  `scripts/code-quality-configs/`) — тоже пока только для шести
  принятых попыток.
- `NOTE.md` — только там, где часть данных не сохранилась (см. ниже).

**Безопасность в смысле чистоты эксперимента, не секретов.** `code/`
содержит полные рабочие реализации Syncbox на двух языках — по духу
ровно то, чем был `acceptance/reference-impl` в исходном инциденте
контаминации. Закрыто той же файловой песочницей: `sandbox.filesystem.
denyRead` в `scripts/run-pilot-ticket.sh` блокирует чтение
родительской директории пилота, а `docs/pilot-runs/` лежит внутри
этого же мета-репозитория — под тем же денаем, что и
`acceptance/reference-impl`. Инвариант, который нельзя нарушать:
`docs/SYNCBOX-SPEC.md` никогда не должен называть или описывать
`docs/pilot-runs/` по пути — иначе получим точную копию исходного
инцидента с новым именем директории. При написании будущих промптов
(Ruby, TypeScript и далее) — не ссылаться на то, как это сделано на
Python/Go, даже переписывая своими словами.

## Что здесь не хранится

Полные транскрипты сессий (`~/.claude/projects/.../<session_id>.jsonl`)
— на порядки больше по объёму, чем `result.json` (сотни KB — единицы
MB на сессию, в основном служебные `tool_use`/`tool_result` шаги), и
существуют только локально на хосте, где запускался пилот, не в этом
репозитории. `result.json` содержит итоговый самоотчёт модели и все
метрики (токены, стоимость, время) — для большинства целей peer-review
этого достаточно; для более глубокой проверки (например, чтобы
убедиться, что скан на контаминацию в `docs/EXPERIMENT-LOG.md` и
инцидент-доках честный) нужен доступ к самому хосту — `session_id`
выше однозначно указывает нужный файл.

## Начиная с какого прогона архивация автоматическая

С правки в `scripts/run-pilot-ticket.sh` от 2026-08-21 — каждый вызов
сам архивирует сюда, в `<язык>/ticket-<N>/<session_id>/`, сразу после
завершения, без ручного шага и без риска перезаписи следующей попыткой
(та причина, по которой два прогона тикета 2 на Go выше — без
оригинального `result.json`): `prompt.txt`, `SYNCBOX-SPEC.md`,
`syncbox-openapi.yaml`, `result.json`, `code/` (снимок директории
пилота) и `quality-quality.json` (code quality против этого кода —
то, что CLAUDE.md называл «прогнать в CI», раньше делалось только
вручную, теперь часть того же автоматического вызова).

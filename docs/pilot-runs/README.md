# Архив прогонов пилота

Полный набор входных и выходных данных по каждой попытке каждого
тикета — промпт, копия спецификации/схемы, которую видел агент, и
результат вызова (`--output-format json`). Ничего не скрыто и не
сглажено: аннулированные и провальные попытки архивированы наравне с
принятыми — сводки в `docs/EXPERIMENT-LOG.md` и `docs/PILOT-RESULT-*.md`
опираются на эти файлы, а не наоборот.

Структура: `<язык>/ticket-<N>/attempt-<M>-<session_id>-<исход>/`, в
каждой попытке:

- `prompt.txt` — тикет, буквально то, что подавалось на stdin `claude -p`.
- `SYNCBOX-SPEC.md`, `syncbox-openapi.yaml` — копия спецификации/схемы
  в директории пилота на момент этого вызова (не всегда идентична
  текущей `docs/SYNCBOX-SPEC.md` меты — см. находку про устаревшую
  копию в
  [инциденте](../incidents/2026-08-19-python-ticket1-contamination/README.md#устаревшая-копия-спецификации-2026-08-20)).
- `result.json` — сырой вывод `--output-format json`: модель, effort,
  токены, стоимость, время, `session_id`, итоговый самоотчёт модели.
- `transcript.jsonl` — полный JSONL-транскрипт сессии (все ходы,
  вызовы инструментов, промежуточные сообщения) — только для прогонов
  начиная с Docker-обвязки харнеса (см. «Что здесь не хранится» ниже),
  для более ранних прогонов недоступен в архиве.
- `code/` — код, который написал агент (полный снимок директории
  пилота на момент этой попытки, без служебных файлов вроде
  `.ticket-N-prompt.txt`). Автоматически архивируется на каждый вызов
  начиная с правки `scripts/run-pilot-ticket.sh` от 2026-08-21 — все
  попытки на Docker-харнессе (раунды 2 и 3 в таблицах ниже) имеют
  `code/`, за исключением одной (Go, `47ced9a7` — упала рейт-лимитом
  до строки архивации, фикс `CLAUDE_EXIT` внесён сразу после находки,
  см. `NOTE.md` в её архиве). Для более ранних (раунд 1, старый
  харнесс) попыток — архивирован только для шести на тот момент
  принятых («сошлось») попыток, по одной на тикет каждого языка; для
  аннулированных/провальных попыток того периода кода нет.
- `quality-quality.json` — code quality по этому конкретному коду
  (`scripts/run-code-quality.sh`, конфиг из
  `scripts/code-quality-configs/`) — тот же охват, что и `code/` выше.
- `NOTE.md` — только там, где часть данных не сохранилась (см. ниже).

**Безопасность в смысле чистоты эксперимента, не секретов.** `code/`
содержит полные рабочие реализации Syncbox на двух языках — по духу
ровно то, чем был `acceptance/reference-impl` в исходном инциденте
контаминации. С 2026-08-21 закрыто внешней, обеспечиваемой ядром ОС
изоляцией контейнера (`scripts/pilot-harness.Dockerfile`, разбор —
[docs/incidents/2026-08-21-write-tool-sandbox-escape/](../incidents/2026-08-21-write-tool-sandbox-escape/README.md)):
внутрь контейнера, где выполняется `claude -p`, примонтирована только
директория конкретного пилота — ни `docs/pilot-runs/`, ни остальной
мета-репозиторий физически не существуют в файловой системе процесса,
их нечем прочитать независимо от текста промпта. До этой правки
границу держала только внутренняя файловая песочница Claude Code
(`sandbox.filesystem.denyRead`) — оказалась нерабочей для инструментов
Read/Write, см. тот же разбор. Инвариант, который тем не менее
остаётся в силе как защита в глубину: `docs/SYNCBOX-SPEC.md` никогда
не должен называть или описывать `docs/pilot-runs/` по пути. При
написании будущих промптов (Ruby, TypeScript и далее) — не ссылаться
на то, как это сделано на Python/Go, даже переписывая своими словами.

## Что здесь не хранится (и что изменилось)

До 2026-08-21 (правка про Docker-обвязку харнеса) полные транскрипты
сессий (`~/.claude/projects/.../<session_id>.jsonl`) существовали
только локально на хосте, где запускался пилот, не в этом
репозитории — для восьми попыток раунда 1 (старый харнесс, таблицы
выше) `transcript.jsonl` в архиве нет и не появится: тот прогон шёл до
Docker-обвязки, файл нигде не сохранён (зависит от `cleanupPeriodDays`
хоста, скорее всего уже вычищен). Начиная с прогонов через
`pilot-harness:latest` (раунды 2–3) — `run-pilot-ticket.sh` копирует
`transcript.jsonl` в архив автоматически (см. ниже), эта дыра закрыта
на будущее — за одним исключением (`47ced9a7`, см. таблицу Go выше и
её `NOTE.md`). `result.json` по-прежнему содержит итоговый самоотчёт
модели и все метрики (токены, стоимость, время) — для большинства
целей peer review этого достаточно и без транскрипта; `transcript.jsonl`,
когда есть, нужен для более глубокой построчной проверки (например,
скана на контаминацию, разбора зацикливаний, или — как в раунде 2 —
обнаружения незафиксированного `effort`).

## Начиная с какого прогона архивация автоматическая

С правки в `scripts/run-pilot-ticket.sh` от 2026-08-21 — каждый вызов
сам архивирует сюда, в `<язык>/ticket-<N>/<session_id>/`, сразу после
завершения, без ручного шага и без риска перезаписи следующей попыткой
(та причина, по которой два прогона тикета 2 на Go в раунде 1 — без
оригинального `result.json`): `prompt.txt`, `SYNCBOX-SPEC.md`,
`syncbox-openapi.yaml`, `result.json`, `code/` (снимок директории
пилота) и `quality-quality.json` (code quality против этого кода —
то, что CLAUDE.md называл «прогнать в CI», раньше делалось только
вручную, теперь часть того же автоматического вызова). Тем же днём,
после перехода на Docker-обвязку харнеса, добавлен и `transcript.jsonl`
(см. выше). С 2026-08-25 архивация происходит независимо от кода
возврата `claude -p` (`CLAUDE_EXIT` в скрипте) — раньше упавший вызов
(например, рейт-лимитом) обрывал скрипт до строки архивации, см.
`47ced9a7` в таблице Go выше как ровно такой случай, восстановленный
задним числом вручную.

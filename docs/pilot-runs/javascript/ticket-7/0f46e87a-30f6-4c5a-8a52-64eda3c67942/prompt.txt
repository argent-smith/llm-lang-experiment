Проверка снаружи (реальный вызов run-client push с обычной командной строки) нашла баг в текущей реализации тикета 7 (клиент push, только что сделан в этом же репозитории). Нужно исправить.

Симптом: на хосте, где /bin/bash — более старая версия (GNU bash 3.2, без возможностей bash 4.4+; так выглядит системный /bin/bash на macOS — Apple годами не обновляет его из-за лицензии), вызов run-client push <dir> --server <url> падает ещё до вызова docker compose:

./run-client: line 48: ENV_ARGS[@]: unbound variable

Похоже, run-client собирает необязательные дополнительные аргументы (например, переменную окружения, которую нужно передать внутрь контейнера) в bash-массив и разворачивает его как "${ENV_ARGS[@]}" под set -u (nounset). На bash 3.2 (и вообще на любом bash до 4.4) раскрытие "${массив[@]}" для массива, в который ничего не было добавлено, считается обращением к неприсвоенной переменной под nounset и завершает скрипт ошибкой — именно это и происходит при обычном вызове (push <dir> --server <url>, когда переменная окружения SYNCBOX_SERVER не задана и массив остаётся пустым).

Нужно:

- Исправить run-client так, чтобы он корректно работал под set -u при пустом наборе элементов в этом массиве (и вообще в любом другом месте скрипта, где встречается похожая раскрутка массива) — независимо от версии bash, включая версии старше 4.4. Один из рабочих способов — использовать "${ARR[@]+"${ARR[@]}"}" вместо "${ARR[@]}"; подойдёт и любой другой способ, дающий тот же результат.
- Не полагаться в этом скрипте на возможности bash, появившиеся в 4.4 и позже — конвенция запуска (run-server/run-client) должна работать на разных хостах, а не только там, где сам агент её тестирует.
- После фикса — самостоятельно перепроверь на реальном bash 3.2 (например, через docker run bash:3.2 с минимальным репродуктором той же конструкции), что раскрутка пустого массива под set -u больше не падает, и что сам run-client (с этим фиксом) доходит до вызова docker compose, не падая на "unbound variable".

Остальная функциональность push (сравнение SHA-256, загрузка отсутствующих/изменившихся файлов, --server/SYNCBOX_SERVER, работа в Docker через docker compose) уже реализована и не нуждается в изменениях — правь только эту конкретную проблему.

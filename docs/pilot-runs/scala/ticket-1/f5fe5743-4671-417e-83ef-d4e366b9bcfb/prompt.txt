Мы начинаем новый проект Syncbox — самостоятельно хостящееся файловое хранилище с синхронизацией (HTTP-сервер + CLI-клиент). Полная спецификация лежит в файлах SYNCBOX-SPEC.md (контракт, конвенции, что намеренно не специфицируется) и syncbox-openapi.yaml (формальная схема HTTP API) в корне этого репозитория — прочитай их перед началом работы.

Тикет 1: каркас сервера.

Нужно поднять минимальный работающий скелет сервера на Scala:

- Эндпоинт GET /healthz, возвращающий 200.
- Конфигурация через --data-dir <path> (обязателен) и --port <n> (по умолчанию 8080), либо переменные окружения SYNCBOX_DATA_DIR/SYNCBOX_PORT — как описано в разделе «CLI (обязательный контракт)» спецификации.
- Весь код должен исполняться в Docker-контейнере, не напрямую на хосте — обязательное условие, описанное в разделе «Docker-изоляция» спецификации. Заведи Dockerfile и настрой всё Docker-хозяйство через docker compose (не через голые docker run/build) — тоже обязательное требование оттуда же.
- Обёртка запуска: исполняемый файл run-server в корне репозитория, вызываемый как run-server --data-dir <path> --port <n> — конвенция описана в спецификации, без неё сервер не получится проверить автоматическими тестами.

Реализация PUT/GET/DELETE блобов и клиента — отдельные будущие тикеты, в этот тикет не входят. Библиотеки, фреймворк и внутреннее устройство — на твоё усмотрение, спецификация говорит, что это намеренно не специфицируется.

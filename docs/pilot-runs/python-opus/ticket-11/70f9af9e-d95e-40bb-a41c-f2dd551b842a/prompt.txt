Продолжаем проект Syncbox (тикеты 1-10 — каркас сервера, healthz и конфигурация, happy path для PUT/GET блоба, список блобов с метаданными, удаление блоба, защита от directory traversal в key, атомарность записи при параллельных PUT, клиент push, клиент pull, клиент status (dry-run), клиент sync с разрешением конфликтов по правилу спецификации — уже сделаны в этом же репозитории). Тикет 11: обработка сетевых ошибок и частичных сбоев на клиенте.

Полная спецификация — в файлах SYNCBOX-SPEC.md и syncbox-openapi.yaml в корне этого репозитория — прочитай перед началом, если нужно освежить детали. Особенно раздел «Коды возврата и ошибки».

Нужно реализовать:

- Довести обработку ошибок во всех клиентских командах (push, pull, sync, status) до раздела «Коды возврата и ошибки» спецификации:
  - Недоступность сервера (соединение отклонено, имя не резолвится, таймаут соединения или ответа) — понятное сообщение в stderr с указанием причины, ненулевой код возврата, без зависания: на сетевые операции должен стоять явный таймаут, а не бесконечное ожидание.
  - Частичный сбой — если при обработке множества файлов один или несколько падают (ошибка сети на конкретном запросе, сервер вернул 5xx, локальный файл нечитаем), остальные файлы всё равно обрабатываются до конца; в конце — сводный отчёт в stderr по неудачным файлам (какой файл, что случилось); код возврата ненулевой, даже если часть файлов перенеслась успешно.
  - Различать в коде возврата случаи из раздела «Коды возврата и ошибки», если спецификация их разграничивает; если раздел задаёт только «ненулевой» без детализации — достаточно ненулевого, но сообщение в stderr должно давать понять, что именно пошло не так.
- Успешные пути push/pull/sync/status менять не нужно — код возврата 0 и поведение при полном успехе остаются как в тикетах 7-10.
- Новых подкоманд нет. Обёртки run-client / run-server / run-tests в корне репозитория уже на месте — меняется только надёжность существующих команд.
- Штатные тесты на новую функциональность обязательны (раздел «Критерии приёмки» спецификации) и запускаются через уже существующую обёртку run-tests. Покрой ими как минимум: сервер недоступен (соединение отклонено) → понятное сообщение в stderr, ненулевой код возврата, нет зависания; таймаут (сервер принимает соединение, но не отвечает в разумный срок) → то же; частичный сбой при push или sync (один файл из нескольких падает, например сервер отвечает 5xx на конкретный key) → остальные файлы перенесены, в отчёте — упавший файл, код возврата ненулевой; частичный сбой при pull (один GET падает) → аналогично.
- Клиент, как и сервер, исполняется в Docker-контейнере через docker compose, не напрямую на хосте — то же требование раздела «Docker-изоляция», уже выполненное для предыдущих клиентских команд.

Границы этого тикета:

- Это последний тикет стартового бэклога спецификации. Не добавляй функциональность сверх раздела «Коды возврата и ошибки» — ретраи с экспоненциальным backoff, резюмируемые докачки, настраиваемые через флаги таймауты, прогресс-бары и подобное спецификацией не предусмотрены и в объём не входят, если только это прямо не следует из формулировки раздела.
- Сервер трогать не нужно — тикет только про клиент.

Библиотеки, HTTP-клиент и внутреннее устройство — на твоё усмотрение, как и в предыдущих тикетах.

Версия языка в этом проекте зафиксирована: Python 3.12, базовый Docker-образ python:3.12-slim (FROM python:3.12-slim в Dockerfile). Не меняй версию языка и базовый образ.

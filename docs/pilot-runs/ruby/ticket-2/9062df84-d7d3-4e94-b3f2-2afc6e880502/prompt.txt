Продолжаем проект Syncbox (тикет 1 — каркас сервера с /healthz — уже сделан в этом же репозитории). Тикет 2: happy path для PUT/GET блоба.

Полная спецификация — в файлах SYNCBOX-SPEC.md (контракт, конвенции) и syncbox-openapi.yaml (формальная схема HTTP API) в корне этого репозитория, они уже здесь — прочитай перед началом, если нужно освежить детали.

Нужно реализовать:

- PUT /blobs/{key} — тело запроса это сырые байты содержимого блоба. Сохранить блоб под ключом key, вернуть 201 и JSON {"key", "sha256", "size"} (sha256 — хеш содержимого в hex, size — размер в байтах).
- GET /blobs/{key} — вернуть 200 и байты блоба, если он существует; 404, если нет.
- key — POSIX-путь относительно корня хранилища, может содержать вложенные директории (например docs/readme.txt) — соответствующие поддиректории на диске нужно создавать по мере необходимости.

Границы этого тикета — только happy path:

- Защита от directory traversal в key (.., абсолютные пути и т.п.) — отдельный будущий тикет, в этот не входит.
- Атомарность записи при параллельных PUT по одному и тому же ключу — тоже отдельный будущий тикет.
- GET /blobs (список блобов) и DELETE /blobs/{key} — тоже отдельные будущие тикеты.

Не реализовывай перечисленное выше заранее — не входит в объём этого тикета.

Сервер по-прежнему должен исполняться в Docker-контейнере через docker compose (Dockerfile/docker-compose.yml/run-server уже есть из тикета 1) — не переделывай эту часть, если она уже работает, расширяй по необходимости для новой функциональности.

Библиотеки и внутреннее устройство хранения блобов на диске — на твоё усмотрение, как и в тикете 1.

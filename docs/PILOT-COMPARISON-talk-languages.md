# Сравнительный отчёт: языки доклада (Python, JavaScript, TypeScript, Ruby)

Все четыре языка идут в CFP и сам доклад RubyRussia 2026 (CLAUDE.md,
«Языки доклада»). Go/OCaml/Scala сюда намеренно не входят — данные по
ним собираются про запас для другого материала, смешивать нельзя (см.
поле «В докладе» в [`docs/EXPERIMENT-LOG.md`](EXPERIMENT-LOG.md)).

Python и Go делили общую, менявшуюся по ходу дела инфраструктуру
пилота (три раунда харнеса — подробный разбор в
[`docs/PILOT-COMPARISON-python-go.md`](PILOT-COMPARISON-python-go.md)),
и данные Python ниже — это канонический раунд 3 той истории
(2026-08-25, Docker-харнесс, `--effort xhigh` явно). JavaScript,
TypeScript и Ruby прогонялись позже (2026-08-26), уже на финальной,
стабильной версии того же харнеса с первой попытки — без собственной
истории раундов. Итог: все 12 канонических тикетов ниже — под
буквально одной конфигурацией (модель, effort, Docker-изоляция) от
начала до конца, разные календарные даты прогона на это не влияют.

«Время» везде ниже — `duration_ms` конкретного вызова `claude -p`
(точное определение — раздел «Лог» в [CLAUDE.md](../CLAUDE.md)), не
календарное время работы над тикетом: не включает паузы между
попытками (переигровки, ожидание сброса рейт-лимита) и не может их
включать — headless-вызов не имеет точки, где мог бы остановиться и
ждать кого-то.

Модель — `claude-sonnet-5`, effort — `xhigh` на всех 12 канонических
прогонах (`grep` по `"effort":"..."` в каждом архивном
`transcript.jsonl`, не предположено). Долларовая стоимость сама по
себе малоинформативна без токенов (конфлирует четыре категории с
разной ценой за единицу) — токены приведены отдельно в таблице ниже,
не только доллары. Известный, принятый как есть побочный эффект
headless-режима на всех прогонах: каждый вызов несёт небольшое
сопутствующее использование `claude-haiku-4-5` (~1500 токенов,
~$0.0015, `modelUsage` результата, отдельно от основного `usage`) —
одинаково на каждом вызове, не искажает сравнение между языками.

Относительно Python (самый дешёвый и быстрый из четырёх): JavaScript
дороже на 55% и медленнее на 51%; TypeScript дороже на 77% и
медленнее на 84%; Ruby дороже на 171% (в 2.7 раза) и медленнее на
185% (в 2.85 раза). Порядок устойчив и по стоимости, и по времени
одновременно (не расходится, как могло бы при разной цене токенов
разных категорий) — Python < JavaScript < TypeScript < Ruby на обеих
осях.

Это наблюдение пилотной фазы, не результат: 3 тикета на язык —
слишком мало для статистической значимости (CLAUDE.md прямо это
подчёркивает), и сама по себе стоимость/время — это не то, что
проверяет гипотеза доклада (гипотеза — про то, *справляется* ли агент
с тикетами по языку, не про скорость), в лучшем случае косвенный
сигнал: больше токенов и внутренних шагов может означать больше
самокоррекции/неуверенности модели на менее знакомом ей языке, но
может означать и просто более многословный по конструкции стек
(Ruby: Sinatra + Puma + Rack, больше межбиблиотечных стыков, чем
голый `http` в Node.js-варианте JavaScript) — три тикета не различают
эти две причины.

Включая рейт-лимитную попытку Ruby (тикет 2, session `37f0d6ca`, не
входит в «канонические» — сдался, не сошёлся): Ruby — 25.3 мин, $5.30,
260 / 197161 / 8129080 / 111094 токенов (in/cache-w/cache-r/out)
суммарно, 4 прогона вместо 3. Честная стоимость этого пилота с учётом
реального сбоя инфраструктуры, не только удачных попыток.

## Рейт-лимит — второй независимый сигнал (риск 3 пилотной фазы)

Ruby, тикет 2, первая попытка (2026-08-26) — тот же паттерн, что уже
был на Go (2026-08-24): `429 session limit`, `terminal_reason:
api_error`, точное время сброса в самом ответе API. Второй независимый
случай подтверждает то же самое поведение и ту же митигацию — простой
повтор тем же вызовом `scripts/run-pilot-ticket.sh` после сброса окна,
без ручного вмешательства в промпт или код. Риск 3 (устойчивость цикла
`-p`/`--resume` к рейт-лимитам, CLAUDE.md, «Сначала пилот») по-прежнему
не получил полноценного стресс-теста внутри одной сессии
ревью-фикс-ревью — оба сигнала (Go, Ruby) сошлись с первой же
повторной попытки, реального цикла `--resume` не потребовалось ни
разу за весь пилот всех четырёх языков.

## Code quality

Тулинг — часть автоматической архивации на каждый тикет
(`scripts/run-code-quality.sh`), не ретроактивный снимок. Конфиги —
явные, версионируемые (`scripts/code-quality-configs/`): `ruff`
0.16.4, `eslint` 10.8.1 + `typescript-eslint` 8.67.0 (TS) +
`eslint-plugin-sonarjs` 4.2.0, `rubocop` 1.89.0 + `reek` 6.5.0.

Числа между языками — не показатель «какой язык качественнее», по
той же причине, что и в сравнении Python/Go: разное покрытие правил
разных инструментов, разный объём и стиль кода. Ruby на порядок выше
остальных почти целиком из-за одного cop'а
(`Style/StringLiterals` — двойные кавычки без интерполяции вместо
одинарных, стилистическая, не структурная находка): 476 из 559
находок Ruby (85%) — это один этот cop. Реальные архитектурные находки
(`Metrics/AbcSize`, `CyclomaticComplexity`, `MethodLength`, `reek
TooManyStatements`/`FeatureEnvy`) единичны на каждом тикете, тем же
порядком величин, что у остальных языков. JavaScript выше TypeScript
почти целиком за счёт `sonarjs/publicly-writable-directories` —
находка на литералах `/tmp/...` в тестовых фикстурах (аргументы
`--data-dir` для юнит-тестов, не реальный файловый ввод-вывод),
устойчиво воспроизводится на каждом тикете обоих языков, не признак
разной небезопасности JS против TS.

По ходу пилота найден и исправлен реальный баг тулинга (не находка о
пилотном коде): `scripts/code-quality-configs/{javascript,typescript}/eslint.config.js`
не объявлял `languageOptions.globals` — flat-конфиг ESLint 9+ не знает
Node.js-окружения без явного указания, из-за чего `require`/`process`/
`module` в обычном Node-коде били `no-undef`. На сыром прогоне
JavaScript, тикет 1, это давало 24 из 36 findings шумом; после фикса
(до JS-тикета 2 и до первого прогона TypeScript) — 0 таких находок ни
на одном из оставшихся 5 тикетов JS/TS.

## Поведенческие наблюдения

- **Штатные тесты без явного требования в промпте.** Все четыре языка
  писали юнит-тесты на каждом тикете, не только когда это прямо
  требовалось текстом промпта (сам промпт тикета никогда не просит
  тестов явно — требование зашито в `SYNCBOX-SPEC.md`, раздел
  «Критерии приёмки», с 2026-08-20). Ни один язык не пропустил тесты
  ни на одном из 12 канонических тикетов.
- **Самостоятельно найденные и исправленные баги.** На трёх из
  четырёх языков модель сама обнаружила и починила реальный дефект
  вне прямого объёма тикета, не дожидаясь провала штатной проверки
  снаружи: JavaScript (тикет 3) — `docker compose run` без `--build`
  не пересобирал образ при изменении кода, молча гонял старую версию;
  Ruby (тикет 1) — `rack-protection` резал `Host: example.org` от
  `rack-test`; Ruby (тикет 2) — Sinatra парсит тело запроса как
  `form-urlencoded` до роута, ломая happy path PUT для обычного
  curl-клиента. Python и TypeScript таких находок за собой не
  оставили — не обязательно означает их отсутствие в коде, могли
  быть, но не всплыли на happy-path тестах этих тикетов.
- **Расхождения самоотчёта со счётом тестов.** Дважды на весь пилот
  (Python тикет 3, Ruby тикет 3) — оба раза ошибка в дельте/разбивке
  count, не в итоговом результате: независимая проверка (`docker
  compose run test` для Python, разовый прогон в контейнере для Ruby)
  подтвердила, что все заявленные тесты реальны и проходят, просто
  формулировка прироста самоотчёта была неточной. JavaScript и
  TypeScript — 0 расхождений на всех 6 тикетах.
- **Утечка host-пути через `docker inspect`.** Один случай на весь
  пилот (TypeScript, тикет 1) — агент инспектировал собственный
  контейнер харнеса широким форматом (`.Mounts`), получил от демона
  хоста реальный путь bind-mount'а с именем мета-репозитория. Файловый
  барьер не пробит, находка не использована. Полный разбор —
  [`docs/incidents/2026-08-26-docker-inspect-hostpath-leak/`](incidents/2026-08-26-docker-inspect-hostpath-leak/README.md).
  Тот же паттерн команды (`docker inspect ... --format
  '{{json .Mounts}}'`) применялся ещё 4 раза на остальных тикетах (TS
  тикет 2, Ruby тикеты 1 и 3) без утечки — цель инспекции была не
  собственным контейнером харнеса, а compose-контейнером проекта с
  нейтральным source-путём.

## Соответствие спецификации

Отклонений от `docs/SYNCBOX-SPEC.md`/`docs/syncbox-openapi.yaml` не
найдено ни на одном из 12 канонических тикетов ни одного из четырёх
языков: границы тикетов соблюдены в обе стороны (ни один самоотчёт не
забежал вперёд на traversal-защиту/атомарность/DELETE, ни один не
пропустил часть объявленного тикета). Отдельно проверено: код Ruby,
архивированный по итогам тикета 1, содержит только `GET /healthz` —
ложная тревога при разборе тикета 2 (самоотчёт модели упомянул, что
PUT/GET «уже существовали», по формулировке похоже на утечку объёма
тикета 1 в тикет 2) снята прямой сверкой архива, речь шла о коде,
написанном в рамках самого тикета 2. Риск 2 пилотной фазы
(«соответствие спецификации между языками», CLAUDE.md, «Сначала
пилот») закрыт для всех четырёх языков доклада без единого случая
превышения объёма.

Прямое побайтовое сравнение HTTP-ответов между всеми четырьмя языками
(коды статусов, форма JSON, формат `modified_at`) не проводилось как
отдельный шаг этого отчёта — вывод о соответствии опирается на
самоотчёты реализаций и независимую проверку тестов/контаминации, не
на сквозной diff ответов. При масштабировании пилота в полный прогон
имеет смысл добавить как отдельную проверку.

## Рекомендация

Все четыре языка доклада прошли пилот (3/3 тикета каждый, кроме
одной ожидаемой переигровки Ruby из-за рейт-лимита) под одной,
полностью зафиксированной конфигурацией харнеса. Риски 1 и 2 пилотной
фазы (CLAUDE.md, «Сначала пилот») закрыты для всех четырёх языков —
утечка контекста мета-репозитория не нашлась ни разу за пределами
одного узкого, разобранного и не повлиявшего на результат случая;
превышений объёма спецификации нет. Риск 3 (устойчивость к
рейт-лимитам) получил второй независимый сигнал того же характера, но
по-прежнему не полный стресс-тест цикла `--resume`.

Три тикета на язык — по-прежнему слишком мало для статистической
значимости, выводы этого отчёта — наблюдения пилотной фазы, не
результат доклада (CFP обещает гипотезу и первые наблюдения к
октябрю, не готовые выводы — CLAUDE.md, «Не делать»). Стоимостной и
временной разрыв (Python дешевле/быстрее Ruby в 2.7–2.85 раза) —
интересное наблюдение, но не прямая проверка гипотезы доклада (объём
кода языка в обучающей выборке против того, справляется ли агент с
тикетами) — полный прогон (10–100 тикетов на язык) нужен, чтобы
отличить языковой эффект от шума единичных генераций.

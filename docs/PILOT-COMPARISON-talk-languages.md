# Сравнительный отчёт: языки доклада (Python, JavaScript, TypeScript, Ruby)

Все четыре языка идут в CFP и сам доклад RubyRussia 2026 (CLAUDE.md,
«Языки доклада»). Go/OCaml/Scala сюда намеренно не входят — данные по
ним собираются про запас для другого материала, смешивать нельзя (поле
«В докладе» в [`docs/EXPERIMENT-LOG.md`](EXPERIMENT-LOG.md)).

Охват: **весь стартовый бэклог `docs/SYNCBOX-SPEC.md` — тикеты 1–11,
канонические прогоны, все четыре языка** (44 прогона). Предыдущая версия
этого отчёта покрывала только тикеты 1–3; она сохранена в истории git.

Модель — `claude-sonnet-5`, effort — `xhigh` на всех 44 канонических
прогонах (проверено `grep` по `"effort"` в архивных `transcript.jsonl`,
не предположено). Это единственные две переменные, зафиксированные от
начала до конца. **Метод при этом дрейфовал** — см. следующий раздел;
без этого сравнение читается точнее, чем оно есть.

«Время» ниже — `wall_ms` попытки: `container_wall_ms` (внешний замер
`run-pilot-ticket.sh` вокруг `docker run`) для тикетов 10–11,
`duration_ms` вызова `claude -p` для тикетов 1–9. Не календарное время
над тикетом: не включает паузы между попытками (переигровки, ожидание
сброса рейт-лимита) и не может их включать — headless-вызов не имеет
точки, где остановился бы и ждал.

Долларовая стоимость сама по себе малоинформативна без токенов
(конфлирует четыре категории с разной ценой за единицу) — токены
приведены отдельно. Наименее искажённый единичный прокси нагрузки —
**out-токены** (генерация модели), по нему считаются ранги ниже.
Побочный эффект headless-режима на всех прогонах: сопутствующее
использование `claude-haiku-4-5` (~2400 in / ~15 out на вызов,
`modelUsage` отдельно от `usage`) — одинаково на каждом вызове, не
искажает сравнение между языками.

## Ранги по тикетам (главный аналитический срез)

Ранг = место языка внутри одного тикета (1 — самый дешёвый, 4 — самый
дорогой). Снимает разброс размера тикетов; усреднён по 12 полным
строкам (тикеты 1–11 + `12-readside`).

| Метрика                                | Python   | JavaScript | TypeScript | Ruby |
| -------------------------------------- | -------- | ---------- | ---------- | ---- |
| средний ранг по out-токенам            | **2.00** | **1.92**   | 2.83       | 3.25 |
| средний ранг по `num_turns`            | **1.75** | 2.17       | 2.83       | 3.25 |
| побед (самый дешёвый по out на тикете) | 5        | 4          | 2          | 1    |

В среднем по тикетам: **{Python, JavaScript} дешевле {TypeScript,
Ruby}**, Ruby — худший, TypeScript — второй. Но по стратам этот
порядок держится не целиком — держатся два факта из трёх:

| Страта (сумма $)                 | JS ×Python | TS ×Python | Ruby ×Python |
| -------------------------------- | ---------- | ---------- | ------------ |
| S1 — ручной, DooD (т1–7)         | ×1.06      | ×1.27      | **×2.03**    |
| S2 — скрипт., DooD (т8–9)        | ×0.98      | ×1.30      | **×0.85**    |
| S3 — скрипт., DinD-фикс (т10–11) | ×0.91      | ×1.43      | ×1.18        |
| C — весь бэклог (т1–11)          | ×1.00      | ×1.33      | ×1.57        |

Суммы $ по C: Python $14.30, JavaScript $14.24, TypeScript $18.95,
Ruby $22.38.

**Что действительно устойчиво:**

- **TypeScript дороже Python на каждой страте** (×1.27 / ×1.30 / ×1.43
  / ×1.33) — и по $, и по ходам, и по out-токенам.
- **JavaScript ≈ Python на каждой страте** (×1.06 / ×0.98 / ×0.91 /
  ×1.00). На поздних клиентских тикетах JS уходит вперёд Python.

**Что НЕ устойчиво — Ruby.** Худший с большим отрывом в ручную эру
(S1, ×2.03 — тянут тикеты 2 и 7, где out-токены к Python ×5.5 и ×12) и
на полном бэклоге (C, ×1.57), но на скриптованном DooD (S2) — **самый
дешёвый из четырёх** (×0.85, целиком из-за аномально короткого тикета 8:
$0.58, 25 ходов), на DinD-фиксе (S3) — в середине, ниже TypeScript.
`n = 2` на S2/S3: одна дешёвая генерация переворачивает знак. То есть
«Ruby дороже всех» — это утверждение про ручную эру и про полный
бэклог, а не универсальное.

| тикетов с >1 итерацией          | 1 (t7) | 1 (t7)     | 0          | 0     |

**По бинарной метрике «справился ли агент» языкового эффекта нет:** все
четыре языка закрыли весь стартовый бэклог, все штатные тесты зелёные,
весь контракт зелёный. Многократная итерация случилась дважды — Python
и JavaScript на тикете 7, и оба раза причина одна и та же (баг в
bash-обёртке `run-client`, общий, не языковой). Единственный провал
«уровня спецификации» за весь пилот — Python на внеплановом тикете
`12-readside` (агент правил контракт, «сдался за 3 итерации»); он не в
стартовом бэклоге.

Различия между языками — целиком в **цене успеха** (токены, ходы,
время), не в самом факте успеха. `smoke` локально стабильно 4/13 на
поздних тикетах у всех четырёх — задокументированный флак Docker
Desktop (протухший client-образ), не код; на CI (чистый Linux) — 13/13.

## Рейт-лимит — по-прежнему без стресс-теста цикла (риск 3 пилота)

За весь пилот четырёх языков — минимум четыре независимых эпизода
`429 session limit` / `529 Overloaded` (`terminal_reason: api_error`,
точное время сброса в ответе API): Go (2026-08-24), Ruby т2
(2026-08-26), TypeScript т5 (2026-08-28), плюс серия на переигровке
тикета 10 и на тикете 11 (TS: 529, затем 429 — дважды). Каждый раз
митигация одна: простой повтор тем же вызовом `run-pilot-ticket.sh`
после сброса окна, без правки промпта или кода. **Все повторы сошлись с
первой же попытки** — полноценного цикла `--resume` через рейт-лимит не
потребовалось ни разу, то есть риск 3 (устойчивость `-p`/`--resume` к
рейт-лимитам, CLAUDE.md «Сначала пилот») по-прежнему не получил стресс-
теста, а получил многократное подтверждение, что до `--resume` дело не
доходит. В «Время» и «Стоимость» отчёта ожидание сброса не входит
(headless-вызов не ждёт).

## Поведенческие наблюдения

- **Штатные тесты без явного требования в промпте.** Все четыре языка
  писали тесты на каждом из 11 тикетов. Ни один не пропустил.
- **Самостоятельно найденные и починенные баги вне объёма тикета.** На
  ранних тикетах: JavaScript (т3) — `docker compose run` без `--build`
  гонял старый образ; Ruby (т1) — `rack-protection` резал `Host`;
  Ruby (т2) — Sinatra парсил тело до роута, ломая PUT. На тикете 10
  (переигровка) Python на 2-й итерации нашёл латентный серверный 500
  (`GET /blobs/{key}` с байтом CR → `ValueError` в Werkzeug) —
  контракт-фаззер поймал, агент починил минимально. На тикете 11 все
  четыре завели инфраструктуру обработки сбоев по своей инициативе
  (Ruby — `lib/syncbox/failure.rb` + тест-дубли `flaky_server` /
  `blackhole_server`; TS — слой `src/net.ts`).
- **Соответствие спецификации.** Отклонений от
  `SYNCBOX-SPEC.md` / `syncbox-openapi.yaml` не найдено ни на одном из
  44 канонических прогонов: границы тикетов соблюдены в обе стороны
  (никто не забежал вперёд, никто не срезал объявленный объём). Риск 2
  пилота закрыт для всех четырёх языков. Сквозной побайтовый diff
  HTTP-ответов между языками как отдельный шаг не проводился — вывод
  опирается на самоотчёты + независимую проверку тестов и контаминации
  + зелёный контракт; при полном прогоне стоит добавить.
- **Утечки контекста мета-репозитория.** За пределами разобранных и не
  повлиявших на результат случаев (`docker inspect` host-path на TS т1;
  DooD host-FS на Ruby т9; всё закрыто переходом на DinD) — не
  нашлось. Риск 1 пилота закрыт.

## Отношение к гипотезе доклада

Гипотеза (CLAUDE.md): Python в фаворе как язык авторов LLM; JavaScript и
TypeScript в фаворе по массовости; Ruby проигрывает по обеим причинам.
Что видно на этих данных:

- **Python в фаворе — согласуется.** Лучший или в паре лучших на 8 из
  12 тикетов, средний ранг ~2.0, доминирует на серверном каркасе
  (тикеты 1–4).
- **JavaScript в фаворе — согласуется.** Средний ранг ~1.9–2.2,
  выигрывает поздние клиентские тикеты, на полном бэклоге вровень с
  Python.
- **TypeScript в фаворе «по массовости» — не подтверждается.** TS
  дороже Python **на каждой из трёх страт** (×1.27 / ×1.30 / ×1.43),
  средний ранг по тикетам ~2.8, на S3 (самая чистая методика) дороже
  Ruby. Гипотеза объединяла JS и TS в один «массовый» механизм; данные
  их разводят. Возможные причины (эти данные не различают): лишний слой
  `tsc` + `tsconfig` как реальная работа, а не немилость к языку; TS в
  обучающей выборке всё же заметно меньше, чем JS, вопреки
  «массовости»; всплеск на тикете 7 (×7.67 к Python) тянет средние.
- **Ruby проигрывает по обеим — в ручную эру и на полном бэклоге, да;
  универсально — нет.** Худший с большим отрывом на S1 (×2.03) и на C
  (×1.57, средний ранг 3.25) — согласуется с прогнозом. Но на S2
  (скриптованный DooD) Ruby — самый дешёвый из четырёх, на S3 — ниже
  TypeScript, и выиграл тикет 8. При `n = 2` на S2/S3 знак
  переворачивает одна короткая генерация — то есть «Ruby хуже всех» на
  этих данных верно для ручной эры, но не для скриптованной.

## Рекомендация

Стартовый бэклог `SYNCBOX-SPEC.md` (11 тикетов) закрыт для всех четырёх
языков доклада. Риски 1 и 2 пилотной фазы (CLAUDE.md, «Сначала пилот»)
закрыты; риск 3 — многократно подтверждён как «до `--resume` не
доходит», без стресс-теста самого цикла.

**Главное для доклада, без натяжки:**

1. По бинарному критерию «агент справился с тикетом» — эффекта языка
   нет: 4/4 языка × 11/11 тикетов сошлись, все тесты и контракт зелёные.
2. Два устойчивых знака в **цене** успеха, на всех трёх стратах:
   **JavaScript ≈ Python** и **TypeScript дороже Python** (×1.27–1.43).
   Третий язык — Ruby — волатилен: дороже всех в ручную эру (S1, ×2.03)
   и на полном бэклоге (C, ×1.57), но дешевле всех на скриптованном
   DooD (S2, ×0.85). `n = 2` на скриптованных стратах.
3. Прогноз гипотезы оправдался для Python и JavaScript; для TypeScript
   — не оправдался (дороже Python везде, на чистейшей методике дороже
   Ruby); для Ruby — оправдался в ручную эру и в сумме, но не в
   скриптованной.

Всё это — наблюдения пилотной фазы, не результат доклада: `n` от 2
(S2/S3) до 11 (C) тикетов на язык, статистический тест на таких
объёмах не осмыслен, и стоимость/скорость — косвенный прокси, а не
прямая проверка гипотезы (объём кода языка в обучающей выборке против
того, справляется ли агент). CFP обещает гипотезу и первые наблюдения
к октябрю, не выводы (CLAUDE.md, «Не делать»). Полный прогон (10–100
тикетов на язык) нужен, чтобы отличить языковой эффект от шума единичных
генераций и, отдельно, чтобы расщепить причину дороговизны Ruby/TS
(самокоррекция на менее знакомом языке против объективно более
многословного стека).

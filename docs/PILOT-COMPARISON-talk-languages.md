# Сравнительный отчёт: языки доклада (Python, JavaScript, TypeScript, Ruby)

Все четыре языка идут в CFP и сам доклад RubyRussia 2026 (CLAUDE.md,
«Языки доклада»). Go/OCaml/Scala сюда намеренно не входят — данные по
ним собираются про запас для другого материала, смешивать нельзя (поле
«В докладе» в [`docs/EXPERIMENT-LOG.md`](EXPERIMENT-LOG.md)).

Охват: **весь стартовый бэклог `docs/SYNCBOX-SPEC.md` — тикеты 1–11,
все четыре языка, 44 канонических прогона**, собранных одной
replay-кампанией 2026-09-04..06 (`scripts/run-pilot-replay.sh`).
Предыдущая версия отчёта делила бэклог на три методические страты
(S1/S2/S3) из-за дрейфа харнеса по ходу пилота; кампания перегнала весь
бэклог под единой конфигурацией, и страты схлопнулись в одну. Ещё более
ранняя версия покрывала только тикеты 1–3. Обе сохранены в истории git.

## Единая конфигурация (было три страты — стало одна)

| Ось             | Значение на всех 44 прогонах                                                 |

| Модель / effort | `claude-sonnet-5` / `xhigh` — явно на каждом вызове                          |
| Гейты           | `tests` block, `contract` block, **`smoke` info** (см. оговорку ниже)        |
| Контракт        | `/data` на tmpfs, `--generation-deterministic`, 3×, `schemathesis==4.24.3`   |
| Промпт          | verbatim initial-промпт тикета из архива прошлых прогонов                    |

**Оговорка про `smoke`.** По исходному плану гейт `smoke` должен был
быть `block` (тикеты 8–11 сделаны, шаги смока 08–11 больше не падают by
design). Кампания гналась на macOS-хосте, где `smoke` стабильно даёт
4/13 из-за задокументированного флака Docker Desktop (протухший
client-образ, не код; на Linux CI — 13/13). Поэтому `smoke` оставлен
`info`. Один побочный эффект этого пойман и устранён: на TypeScript
тикете 8 вызов `claude -p` оборвался (`result` — сериализованный вызов
инструмента, не финальное сообщение; 1 ход, `pull` не написан), а
`tests`/`contract` прошли на коде тикета 7 — `smoke` в режиме `block`
это бы заблокировал. TS тикеты 8–11 перегнаны с архивной базы тикета 7;
в `scripts/run-pilot-loop.sh` добавлен гард на оборванный вызов.
Остальные 43 ячейки — `verify-replay.py` PASS, блокирующие гейты
настоящие.

«Время» ниже — `container_wall_ms` (внешний замер `run-pilot-ticket.sh`
вокруг `docker run`): полное время попытки, кроме пауз между вызовами
`claude -p` — те в него не входят и не могут (headless-вызов не
останавливается ждать). Разбивка `model / infra / work` —
`analyze-timing-breakdown.py` по транскрипту.

Долларовая стоимость сама по себе малоинформативна (конфлирует четыре
категории токенов с разной ценой) — токены приведены отдельно.
Наименее искажённый единичный прокси нагрузки — **out-токены**, по нему
считаются ранги.

## Ранги по тикетам (главный аналитический срез)

Ранг = место языка внутри одного тикета (1 — дешевле/меньше, 4 —
дороже/больше). Снимает разброс размера тикетов; усреднён по 11 тикетам.

| Метрика                       | Python   | JavaScript | TypeScript | Ruby |
| ----------------------------- | -------- | ---------- | ---------- | ---- |
| средний ранг по out-токенам   | **2.09** | 3.09       | 2.64       | 2.18 |
| средний ранг по num_turns     | **1.64** | 3.27       | 2.73       | 2.36 |
| побед (ранг 1 по out-токенам) | 4        | 1          | 2          | 4    |

Порядок по цене под единой методикой:
**Ruby ($15.22) < JavaScript ($16.24) ≈ Python ($16.42) < TypeScript
($18.60)**. По out-токенам: Ruby (×0.85) < JavaScript (×0.94) < Python
(×1.00) ≈ TypeScript (×1.00). По ходам и рангам Python — самый экономный,
JavaScript — самый многоходовый.

## Что изменилось против предыдущей (стратифицированной) версии

- **«Ruby дороже всех» не воспроизвёлся.** В прошлой версии Ruby шёл
  ×1.57–2.03 к Python по сумме $ и был худшим по среднему рангу (3.25).
  Под единой методикой Ruby — **самый дешёвый** по $ (×0.93) и по
  out-токенам (×0.85), средний ранг 2.18. Прежний результат тянула
  ручная эра (страта S1: тикеты 2 и 7, где out-токены к Python были ×5.5
  и ×12). Это сам по себе вывод: заметная доля «языкового эффекта» в тех
  данных была эффектом инструмента и оператора, а не языка.
- **Python и JavaScript ≈ равны по деньгам** (×1.00 / ×0.99), но
  расходятся по ходам: Python тратит меньше всех ходов (ранг 1.64),
  JavaScript — больше всех (ранг 3.27). При равной цене JavaScript идёт
  более длинным путём.
- **TypeScript дороже всех по $ (×1.13) и по ходам (×1.18).** Сигнал
  «TS дороже Python» уцелел, но ослаб против прежних ×1.27–1.43 и теперь
  измерен на одной чистой страте. По out-токенам TS вровень с Python.
- **Ruby медленный по wall-времени, но не по модели.** Ruby — второй по
  суммарному wall (76.6 мин) после TypeScript, но его `model`-время
  наименьшее из четырёх (54.9 мин); разницу даёт `work` (21.4 мин против
  7.1 у Python) — прогоны тестов и пересборка по ходу лупа. Модель на
  Ruby делает меньше, а цикл проверки дольше.

## Рейт-лимит — по-прежнему без стресс-теста цикла (риск 3 пилота)

За кампанию — 5 эпизодов `429 session limit` (Python т9, JavaScript т7,
TypeScript т5, Ruby т1, Ruby т10) плюс один оборванный вызов без кода
ошибки (TypeScript т8). Каждый 429 — фиксированный оконный лимит
использования (~5-часовое окно), точное время сброса в самом ответе
API; `run-pilot-replay.sh` парсит его, ждёт до сброса + запас и
повторяет ту же ячейку с итерации 1. **Все пять возобновились с первой
же попытки** — полноценного цикла `--resume` через рейт-лимит не
потребовалось ни разу, то есть риск 3 (устойчивость `-p`/`--resume` к
рейт-лимитам, CLAUDE.md «Сначала пилот») получил многократное
подтверждение, что до `--resume` дело не доходит, а не стресс-тест
самого цикла. Суммарные ~19 ч календарных пауз за кампанию в «Время» и
«Стоимость» не входят.

## Поведенческие наблюдения

- **Штатные тесты.** Все четыре языка писали тесты на каждом из 11
  тикетов (`run-tests` обязателен по `SYNCBOX-SPEC.md`). Ни один не
  пропустил.
- **Оборванный вызов `claude -p` (TypeScript т8).** Формально успешный
  результат (`claude_rc=0`, `is_error=false`, `subtype=success`), но
  `result` — сериализованный вызов инструмента, 1 ход, `pull` не
  написан; транскрипт покрыл 34% прогона. Гейты `tests`/`contract` этого
  не видят (прошли на коде тикета 7), а `smoke` был `info`. Разобрано,
  тикеты 8–11 перегнаны с базы тикета 7, в `run-pilot-loop.sh` добавлен
  гард. Инцидент-класс харнеса, не языковой сигнал.
- **Соответствие спецификации.** Отклонений от
  `SYNCBOX-SPEC.md` / `syncbox-openapi.yaml` не найдено ни на одном из
  44 канонических прогонов (`verify-replay.py` PASS: транскрипт валиден,
  0 «No suitable shell found», блокирующие гейты зелёные). Границы
  тикетов соблюдены в обе стороны. Риски 1 и 2 пилота закрыты для всех
  четырёх языков.

## Отношение к гипотезе доклада

Гипотеза (CLAUDE.md): Python в фаворе как язык авторов LLM; JavaScript и
TypeScript — по массовости; Ruby проигрывает по обеим причинам.

- **Python в фаворе — частично.** Самый экономный по ходам (ранг 1.64) и
  по wall-времени, в паре дешёвых по $. Но по out-токенам вровень с
  TypeScript, и по $ дороже Ruby.
- **JavaScript в фаворе «по массовости» — по деньгам да** (вровень с
  Python), **по ходам — нет** (худший из четырёх, ранг 3.27).
- **TypeScript в фаворе «по массовости» — не подтверждается.** Дороже
  Python по $ (×1.13) и по ходам (×1.18), дороже всех четырёх по сумме
  $. Согласуется с тем, что корпус TypeScript в разы тоньше JavaScript и
  Python (`docs/MARKET-PREVALENCE-experiment-languages.md`). Гипотеза
  объединяла JS и TS в один «массовый» механизм; данные их разводят.
- **Ruby проигрывает по обеим — не подтверждается под единой
  методикой.** Ruby — самый дешёвый по $ и out-токенам, средний по
  ходам. Прежний вывод «Ruby дороже всех» оказался в значительной мере
  артефактом дрейфа метода (ручная эра). Единственная ось, где Ruby
  заметно хуже, — `work`-время (медленный цикл тестов/сборки), но модель
  на Ruby делает не больше, а меньше.

## Рекомендация

Стартовый бэклог `SYNCBOX-SPEC.md` (11 тикетов) закрыт для всех четырёх
языков доклада под **одной** зафиксированной конфигурацией — страты
S1/S2/S3 схлопнуты, главная оговорка предыдущего отчёта снята. Риски 1 и
2 пилота (CLAUDE.md, «Сначала пилот») закрыты; риск 3 — многократно
подтверждён как «до `--resume` не доходит», без стресс-теста самого
цикла.

**Главное для доклада, без натяжки:**

1. По бинарному критерию «агент справился с тикетом» — эффекта языка
   нет: 4/4 языка × 11/11 тикетов сошлись, все блокирующие гейты
   зелёные.
2. По цене успеха под фиксированной методикой порядок —
   **Ruby ≤ {Python ≈ JavaScript} < TypeScript** по $ и по out-токенам;
   по ходам самый экономный Python, самый многоходовый JavaScript.
3. Прежний результат «Ruby дороже всех» не воспроизвёлся под единой
   методикой — это сам по себе вывод: часть «языкового эффекта» в тех
   данных была эффектом инструмента и оператора. Прогноз гипотезы
   («Ruby проигрывает по обеим») на этих данных не подтверждается;
   для TypeScript «в фаворе по массовости» — тоже не подтверждается.

Всё это — наблюдения пилотной фазы, не результат доклада: `n = 1` на
ячейку (один канонический прогон на язык на тикет), статистический тест
на таких объёмах не осмыслен, и стоимость/скорость — косвенный прокси, а
не прямая проверка гипотезы (объём кода языка в обучающей выборке против
того, справляется ли агент). `smoke` был `info`, а не `block` — TS
тикет 8 показал, чем это чревато; дыра закрыта переигровкой и гардом, но
на всей выборке метод с `smoke=block` не прогонялся. CFP обещает
гипотезу и первые наблюдения к октябрю, не выводы (CLAUDE.md, «Не
делать»). Полный прогон (10–100 тикетов на язык) нужен, чтобы отличить
языковой эффект от шума единичных генераций.

- **2 инцидента**, оба разобраны и закрыты фиксами (PR #13, PR #14):

  «языкового эффекта» в старых данных была эффектом дрейфа инструмента.

## Зачем понадобился перепрогон

Прежний сравнительный отчёт делил бэклог на три страты, потому что
харнесс дрейфовал по ходу пилота:

| Тикеты | Цикл                                         | Docker-изоляция                      |
| ------ | -------------------------------------------- | ------------------------------------ |
| 1–7    | ручной (оператор гонял гейты между вызовами) | Docker-out-of-Docker                 |
| 8–9    | скриптованный авто-луп                       | Docker-out-of-Docker                 |
| 10–11  | скриптованный авто-луп                       | Docker-in-Docker, починенный харнесс |

Из-за этого главный вывод старого отчёта — «Ruby дороже Python в
2.7–2.85 раза» — нельзя было отделить от эффекта инструмента и
оператора. Кампания перегнала **весь бэклог под конфигурацией
тикетов 10–11**.

## Конфигурация (одна на все 44 прогона)

| Ось             | Значение                                                                     |
| --------------- | ---------------------------------------------------------------------------- |
| Харнесс         | Docker-in-Docker, `scripts/run-pilot-ticket.sh`, базовые образы предзапечены |
| Цикл            | `scripts/run-pilot-loop.sh --max-iters 4` (авто ревью→фикс)                  |
| Модель / effort | `claude-sonnet-5` / `xhigh`, явно на каждом вызове                           |
| Гейты           | `tests` block, `contract` block, `smoke` info                                |
| Контракт        | `/data` на tmpfs, `--generation-deterministic`, 3×, `schemathesis==4.24.3`   |
| Промпт          | verbatim initial-промпт тикета из архива прошлых прогонов                    |
| Оркестратор     | `scripts/run-pilot-replay.sh` — чекпойнт + пауза-до-сброса на 429            |

**`smoke` держали `info`, а не `block`.** По исходному плану гейт должен
был стать блокирующим (тикеты 8–11 сделаны, шаги смока 08–11 больше не
падают by design). Но кампания гналась на macOS-хосте, где `smoke`
стабильно даёт 4/13 из-за задокументированного флака Docker Desktop
(протухший client-образ, не код; на Linux CI — 13/13). Это отклонение
от плана, и оно один раз стрельнуло — см. инцидент с TS/тикет-8.

### Паузы по лимиту 429

5 эпизодов: Python т9, JavaScript т7, TypeScript т5, Ruby т1, Ruby т10.
Каждый — фиксированное оконное окно использования (~5 ч), точное время
сброса в самом ответе API (`api_error_status: 429`,
`terminal_reason: api_error`). Оркестратор парсил время сброса, ждал до
него + запас, повторял ту же ячейку с итерации 1. **Все пять
возобновились с первой же попытки.** Полноценного стресс-теста цикла
`-p`/`--resume` через рейт-лимит по-прежнему нет — до него не доходит
(риск 3 пилота, CLAUDE.md «Сначала пилот»). Суммарные ~19–20 ч
календарных пауз в «Время» и «Стоимость» не входят: headless-вызов не
останавливается ждать.

## Наблюдения (пилотная фаза, `n = 1` на ячейку)

1. **Бинарно «агент справился» — эффекта языка нет.** 4/4 языка × 11/11
   тикетов сошлись, все блокирующие гейты зелёные. Многократная итерация
   случилась ровно раз на язык — на тикете 1 (контракт-гейт как
   блокирующий с первого тикета).
2. **«Ruby дороже всех» не воспроизвёлся.** Под единой методикой Ruby —
   самый дешёвый по $ (×0.93) и по out-токенам (×0.85), средний по
   ходам. Прежний результат (×1.57–2.03 к Python) тянула ручная эра S1.
   Это сам по себе вывод: заметная доля «языкового эффекта» в старых
   данных была эффектом инструмента и оператора, а не языка.
3. **Порядок по цене: Ruby < {Python ≈ JavaScript} < TypeScript.** Python
   и JavaScript равны по деньгам, но расходятся по ходам — Python самый
   экономный (ранг 1.64), JavaScript самый многоходовый (3.27): при
   равной цене JavaScript идёт длиннее.
4. **TypeScript дороже всех** — ×1.13 по $, ×1.18 по ходам. Сигнал
   «TS дороже Python» уцелел, но ослаб против прежних ×1.27–1.43 и
   теперь измерен на одной чистой страте.
5. **Ruby медленный по wall-времени, но не по модели.** Ruby второй по
   суммарному wall (76.6 мин), но его model-время наименьшее из четырёх
   (54.9 мин); разницу даёт `work` (21.4 мин против 7.1 у Python) —
   прогоны тестов и пересборка по ходу лупа. Модель на Ruby делает
   меньше, а цикл проверки дольше.

## Инциденты и починки

### Контаминация JavaScript/тикет-1

`scripts/run-pilot-replay.sh` под `--resume` пропускал проверку «pilot-dir
языка пуст перед его первым тикетом» для всех языков. После того как
Python прошёл 11/11 и оркестратор перешёл к JavaScript, директория
`pilot-runs-live/javascript/` не была очищена — в ней лежала полная
реализация тикетов 1–11 с прошлого пилота. Тикет 1 отработал поверх
чужого кода, сессия контаминирована и выброшена, `claude -p` перезапущен
с чистой директории.

**Фикс** ([PR #13](https://github.com/argent-smith/llm-lang-experiment/pull/13),
смёржен): подкоманда `lang-started` в `scripts/replay-checkpoint.py`;
очистка привязана к состоянию чекпойнта, а не к флагу `--resume` —
уже пройденные языки отсекаются по `is-done`, а не начатые стартуют с
чистой директории.

### Оборванный вызов TypeScript/тикет-8

Вызов `claude -p` для TS/тикет-8 завершился формально успешно
(`claude_rc=0`, `is_error=false`, `subtype=success`, `stop_reason=end_turn`),
но `num_turns=1`, а поле `result` — сериализованный `Bash({...})`, не
финальное сообщение ассистента; транскрипт покрыл 34% прогона. Вероятно
аварийное завершение вызова внутри DinD-контейнера. Код `pull` агент не
написал.

Луп записал «сошлось за 1 итерацию»: `tests` и `contract` (обе `block`)
прошли на коде тикета 7 — структурно не проверяют клиентский `pull`; а
единственный гейт, который проверяет (`smoke`), был `info` из-за флака
Docker Desktop на macOS. Тикеты 9–10 достраивались на неполной базе
(тикет 9 намерил только `status`; тикет 10 — `pull` + `sync` вместе).

**Фикс** ([PR #14](https://github.com/argent-smith/llm-lang-experiment/pull/14),
смёржен): гард в `scripts/run-pilot-loop.sh` — если `result` матчит
`^<ИмяИнструмента>({`, трактовать как `harness_invalid` (итерация не
засчитывается, цикл прерывается), рядом с проверкой «No suitable shell
found». TS тикеты 8–11 перегнаны с архивной базы TS/тикет-7; полнота
кода каждого проверена вручную (`pull.ts` → `status.ts` → `sync.ts`,
`NOT_YET_IMPLEMENTED` сжимается правильно).

### Проверка всех 44 финальных сессий

`scripts/verify-replay.py` по 44 каноническим сессиям — **44 PASS**:
транскрипт валиден, 0 «No suitable shell found», блокирующие гейты
настоящие. `pilot-gates.yml` на CI (чистый Linux) перепроверил
smoke+contract нового канонического TS/тикет-11 — 13/13 смока, контракт
зелёный.

## Оговорки

- **`n = 1` на ячейку** — один канонический прогон на язык на тикет.
  Статистический тест на таких объёмах не осмыслен.
- **Стоимость и скорость — косвенный прокси**, а не прямая проверка
  гипотезы (объём кода языка в обучающей выборке против того,
  справляется ли агент с тикетами).
- **`smoke` был `info`, а не `block`.** TS/тикет-8 показал, чем это
  чревато; дыра закрыта переигровкой и гардом, но метод с `smoke=block`
  на всей выборке не прогонялся.
- Это наблюдения пилотной фазы, **не выводы доклада**. CFP обещает
  гипотезу и первые наблюдения к октябрю, не готовые выводы (CLAUDE.md,
  «Не делать»).
- Полный прогон (10–100 тикетов на язык) нужен, чтобы отличить языковой
  эффект от шума единичных генераций.
